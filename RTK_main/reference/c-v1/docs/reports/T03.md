## 2. 实现要点

- `switch (msg_id)` 分发到每命令一个 `static` 处理函数；单函数均 < 100 行。
- 权限：PHONE 可执行 §4 全部命令与 0x42/0x43/0x44；ALARM 仅 0x41（PUSH，解析心跳，不回复）与 0x40 查询；PENDING/NONE 及其他组合返回 `CMD_RES_DENIED`。
- 未知 ID 与 5.4 保留 ID 由 `is_known_id()` 白名单统一返回 `CMD_RES_NO_REPLY`，不生成帧。
- 0x01 应答按 §4 固定偏移填写（字段间存在保留空隙；board 位于 @56）。首次实现按字段顺序紧凑排列，验收测试 `test_dev_info_0x01` 发现 @56 内容错误后已改为固定偏移。
- 0x44 查询应答长度 = `1 + 6 × 数量`；设置 1 打开配对窗口，设置 0 清空白名单并置 `b_whitelist_changed`。
- 0x0D 设置按 5.4 行为不回复。
- 0x40 查询：seq=0、uptime=now_ms、fix_quality=0xFF，flags bit0 取 `link_mgr_handles(PHONE)`，bit1 取测试覆盖状态。
- 应答 payload 在栈上构造，经 `proto_frame_build` 写入 `p_reply->buf`；无动态内存、无时钟调用。

## 4. 冻结输入冲突（BARR-C 门禁）

`check.sh` 的 clang-tidy 步骤使用安装的 LLVM/Clang 23，其 `HeaderFilterRegex` 默认值为 `.*`，因此会分析被包含的**冻结头文件** `components/cmd/include/cmd_disp.h`。该头文件在 `line 35–43` 使用 `char product[8]`、`char sn[16]` 等字面量数组长度，触发 `readability-magic-numbers`（`WarningsAsErrors: '*'`）。

证据：

```
components/cmd/include/cmd_disp.h:35:21: error: 8 is a magic number ... [readability-magic-numbers]
components/cmd/include/cmd_disp.h:36:16: error: 16 is a magic number ...
... (共 9 处，均位于冻结头文件)
```

另外，直接对冻结头文件运行 `check.sh components/cmd/include/cmd_disp.h` 还会报 `clang-format` 违规（`cmd_disp.h:109/110` 等），说明该冻结文件在安装的 clang-format/clang-tidy 23 下本身无法通过 G5。

处理：未修改任何一个字节的冻结文件，也未通过配置或 `NOLINT` 关闭告警；上述 `--header-filter='^$'` 仅用于证明 `cmd_disp.c` 自身无诊断。
