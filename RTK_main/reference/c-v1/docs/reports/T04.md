## 3. 实现要点

- 初始化顺序：`mem_release(BLE)` → controller init/enable(CLASSIC) → `esp_bluedroid_init_with_cfg` → enable → GAP/SPP 回调 → IO cap `ESP_BT_IO_CAP_NONE` → `esp_spp_enhanced_init(ESP_SPP_MODE_CB)`；任一步失败按逆序释放（无 `goto`）。
- SPP `INIT_EVT` 成功后 `esp_spp_start_srv(ESP_SPP_SEC_NONE, ESP_SPP_ROLE_SLAVE, 0, "SPP_SERVER")`、设置不含换行的设备名、`CONNECTABLE + GENERAL_DISCOVERABLE`。
- GAP：`CFM_REQ` 自动确认；`PIN_REQ` 回固定 4 位 `0000`（兼容旧设备）。
- 会话表：2 个静态 slot，每 slot 静态 `StaticStreamBuffer_t` + 2048 B 存储；`in_use`/句柄/拥塞标志用 `portMUX_TYPE` 临界区保护。
- 事件队列：静态深度 16；回调中 `xQueueSend(..., 0)`，满时计数 + `ESP_LOGW`，不阻塞。
- `DATA_IND`：`xStreamBufferSend(..., 0)`；部分/全部写入失败时投递 `BT_SPP_EVT_RX_DROP` 并携带丢弃字节数。
- `bt_spp_write`：拥塞时用静态 EventGroup 等待 `ESP_SPP_CONG_EVT` 解除，按 `xTaskGetTickCount()` 计算有界超时，超时返回 `ESP_ERR_TIMEOUT`；已核实 IDF 深拷贝，无需保持调用方缓冲区。
- 表满时新连接立即 `esp_spp_disconnect`；未知句柄读取返回 0。
