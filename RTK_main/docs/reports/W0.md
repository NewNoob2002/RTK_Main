# W0 Wi-Fi 资源探测

基线 `56a5ccaa2fb985629b49d38bbdab168377dcc91a`，分支 `spike/w0-wifi-budget`。工具链为 ESP-IDF v6.1 `fff9895c82d744c7237be8847347bdd1b07c6643`、Xtensa GCC 15.2 和 Python 3.13。固件使用 ESP32、DEV 控制台和自动板型识别。

## §1.3 构建与静态用量

IRAM、DRAM、Flash Code、Flash Data 和链接镜像大小来自各构建目录的 `idf.py size` 输出。`.bin` 取 `stat -c %s`，包含打包与对齐。单位均为 B。

| 构建目录 | IRAM | IRAM 余量 | 静态 DRAM | Flash Code | Flash Data | 链接镜像 | `rtk_main.bin` |
|---|---:|---:|---:|---:|---:|---:|---:|
| `builds/w0-baseline` | 86,287 | 44,785 | 73,647 | 600,148 | 161,320 | 869,570 | 869,680 |
| `builds/w0-bt` | 114,715 | 16,357 | 94,795 | 1,075,904 | 255,660 | 1,472,202 | 1,472,320 |
| `builds/w0-wifi` | 114,715 | 16,357 | 94,795 | 1,075,904 | 255,660 | 1,472,202 | 1,472,320 |
| `builds/w0-both` | 114,715 | 16,357 | 94,795 | 1,075,904 | 255,660 | 1,472,202 | 1,472,320 |

相对原始 DEV 基线，共用镜像增加 28,428 B IRAM、21,148 B 静态 DRAM 和 602,640 B `.bin`。Flash Code 与 Flash Data 合计从 761,468 B 增至 1,331,564 B。

BT、WIFI、BOTH 均链接两套射频。BT 只起 SPP。WIFI 在 BootArena 分配前释放 BTDM 控制器内存，跳过 SPP 启动、SPP 缓冲分配和 `bt_link`，保留 GNSS 与控制台。BOTH 先起 BT 再起 SoftAP。SoftAP 使用设备蓝牙名作为 SSID，固定信道 1，最多两个终端，使用 ADR-0017 的 WPA2 默认口令和 IDF 默认 DHCP/IP 配置。HTTPD 固定在 core 0，配置三个客户端套接字。`GET /` 发送 Flash 中的 20,480 B HTML，`/ws` 用 HTTPD 任务独占的 1024 B 静态缓冲回显完整文本和二进制帧。

### P2 v1.41 台架

| 模式 | 启动 free B | 启动 largest B | 打开页面后 free B | 60 s 后 free B | 60 s 后 largest B | 60 s 后 min B |
|---|---|---|---|---|---|---|
| 现状 DEV | PENDING_HIL | PENDING_HIL | — | — | — | — |
| BT | PENDING_HIL | PENDING_HIL | — | — | — | — |
| WIFI | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL |
| BOTH | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL | PENDING_HIL |

1. 每个镜像重启后等待 DEV 提示符和 GNSS 状态稳定，执行 `sys mem`，读取 `heap_caps` 下 `8bit` 行的 `free`、`largest` 和 `min`。`W0 <mode> heap8 …` 是启动放行前的诊断快照。`sys heap` 可旁证内部 8-bit 堆。
2. WIFI 和 BOTH 各接入一台终端，在浏览器打开 `http://192.168.4.1/`，执行一次 `sys mem` 记录打开页面后的空闲堆。浏览器开发者工具可核查根页面的响应体长 20,480 B。保持页面在前台，运行下面的负载。
3. 收到 `60/60` 后立即在 WebSocket 仍打开时再次执行 `sys mem`。`min` 为 IDF 记录的本次启动以来的低水位。本轮有丢帧、错误或复位时记录现象并保留日志。

```javascript
const ws = new WebSocket('ws://' + location.host + '/ws');
const payload = 'x'.repeat(1024);
let sent = 0;
let received = 0;
let timer;
ws.onopen = () => {
    timer = setInterval(() => {
        ws.send(payload);
        if (++sent === 60) clearInterval(timer);
    }, 1000);
};
ws.onmessage = ({data}) => {
    if (data !== payload) {
        clearInterval(timer);
        ws.close();
        throw new Error('Unexpected echo');
    }
    if (++received === 60) console.log('60/60 echoes verified');
};
ws.onerror = () => console.error('WebSocket error');
ws.onclose = () => {
    clearInterval(timer);
    console.log('WebSocket closed, echoes:', received);
};
```

ADR-0017 的 BT 空闲堆降幅 ≤ 8 KiB、WIFI 打开页面后空闲堆 ≥ 40 KiB 两项均为 `PENDING_HIL`。应在同一 P2 上对照基线，并以实际镜像的 G3 结果和 IRAM 余量一并验收。

## §1.4 累加调参

按任务卡次序累加，以 WIFI 默认构建为对照。主交付的三档保留相同的 IDF 默认缓冲配置。各调参目录保留镜像和配置供 Architect 复测。每步的运行期堆值均为 `PENDING_HIL`。

| 步骤 / 构建 | 本步变化 | IRAM | IRAM 余量 | 静态 DRAM | Flash Code | Flash Data | 链接镜像 | `.bin` | 启动 free / largest B | 60 s 后 free / largest / min B |
|---|---|---:|---:|---:|---:|---:|---:|---:|---|---|
| 0 / `builds/w0-wifi` | IDF 默认 | 114,715 | 16,357 | 94,795 | 1,075,904 | 255,660 | 1,472,202 | 1,472,320 | PENDING_HIL | PENDING_HIL |
| 1 / `builds/w0-tune-1` | `CONFIG_ESP_WIFI_STATIC_RX_BUFFER_NUM=4`（10 → 4） | 114,715 | 16,357 | 94,795 | 1,075,904 | 255,660 | 1,472,202 | 1,472,320 | PENDING_HIL | PENDING_HIL |
| 2 / `builds/w0-tune-2` | `CONFIG_ESP_WIFI_DYNAMIC_RX_BUFFER_NUM=8`、`CONFIG_ESP_WIFI_DYNAMIC_TX_BUFFER_NUM=8`（均为 32 → 8） | 114,715 | 16,357 | 94,795 | 1,075,908 | 255,660 | 1,472,206 | 1,472,320 | PENDING_HIL | PENDING_HIL |
| 3 / `builds/w0-tune-3` | `CONFIG_ESP_WIFI_AMPDU_RX_ENABLED=n`、`CONFIG_ESP_WIFI_AMPDU_TX_ENABLED=n` | 114,715 | 16,357 | 94,795 | 1,075,864 | 255,628 | 1,472,130 | 1,472,240 | PENDING_HIL | PENDING_HIL |
| 4 / `builds/w0-tune-4` | `CONFIG_LWIP_TCP_SND_BUF_DEFAULT=5744`、`CONFIG_LWIP_TCP_WND_DEFAULT=5744`（均为 5760 → 5744） | 114,715 | 16,357 | 94,795 | 1,075,864 | 255,628 | 1,472,130 | 1,472,240 | PENDING_HIL | PENDING_HIL |
| 5 / `builds/w0-tune-5` | `-DW0_HTTPD_STACK_BYTES=4096`（显式指定） | 114,715 | 16,357 | 94,795 | 1,075,864 | 255,628 | 1,472,130 | 1,472,240 | PENDING_HIL | PENDING_HIL |

五步的静态 IRAM 和 DRAM 用量一致。关闭 AMPDU 后，链接镜像较上一步减少 76 B，打包镜像减少 80 B。第 4、5 步的静态表项与第 3 步一致。

第一步仍保留 `CONFIG_ESP_WIFI_RX_BA_WIN=6`。IDF `esp_wifi/Kconfig` 建议启用 RX AMPDU 时静态 RX 缓冲数至少等于 BA 窗口。单步探测沿用任务卡顺序，并在第三步关闭 AMPDU 后消除这组配置差异。第五步显式指定 4096 B，等于本机 IDF 的 `HTTPD_DEFAULT_CONFIG()` 默认栈。Wi-Fi 静态 RX 缓冲由 `esp_wifi_init()` 分配，动态 RX/TX 和 lwIP 窗口随运行期流量影响堆，调参收益以台架数据为准。

## §1.5 CM680 星座命令

命令来自《CM680系列高精度模组产品数据接口协议 V1.2.8》§5.1–5.3。`gnss send` 自动追加 CRLF，控制台 `OK` 表示 UART 发送成功。接收机应答原文需由 Architect 在 GNSS RX 线上采集。先用 `gnss status` 确认 CM680 为 running，并用 `MASK` 保存测试前状态。每项操作后重新查询。逐项验证后恢复该星座原有状态。

```text
gnss status
gnss send MASK
gnss send MASK GPS
gnss send MASK
gnss send UNMASK GPS
gnss send MASK
gnss send MASK BDS
gnss send MASK
gnss send UNMASK BDS
gnss send MASK
gnss send MASK GLO
gnss send MASK
gnss send UNMASK GLO
gnss send MASK
gnss send MASK GAL
gnss send MASK
gnss send UNMASK GAL
gnss send MASK
gnss send MASK QZSS
gnss send MASK
gnss send UNMASK QZSS
gnss send MASK
```

QZSS 解除屏蔽使用 §5.3 的通用 `UNMASK [频点/卫星系统]` 语法和表 5-4 的系统名。原始应答（每条命令及查询）为 `PENDING_HIL`。

## 建议的 Wi-Fi 默认配置

先按本次共用配置建立 W1/W2 对照。`ESP_WIFI_ENABLED` 是 ESP32 上由 `SOC_WIFI_SUPPORTED` 驱动的隐藏默认项，项目通过 CMake 链接 `esp_wifi`、`esp_netif`、`esp_event` 和 `esp_http_server`。

```ini
CONFIG_ESP_WIFI_SOFTAP_SUPPORT=y
CONFIG_ESP_COEX_SW_COEXIST_ENABLE=y
CONFIG_HTTPD_WS_SUPPORT=y
```

`CONFIG_ESP_COEX_SW_COEXIST_ENABLE=y` 用于 W0 的 BOTH 对照。若默认 Wi-Fi 档未达标，按调参表在 P2 核对最早达标的配置，再决定是否加入对应的 `CONFIG_ESP_WIFI_*` 和 `CONFIG_LWIP_*` 值。HTTPD 栈 4096 B 由 HTTPD 默认配置给出。

## Architect 验收（Claude，2026-11-19）

P2 v1.41 台架（/dev/ttyACM0，日志 `RTK_Main-w0/RTK_main/builds/w0-hil/*.log`），启动后 10 s `sys mem`：

| 构建 | 启动空闲堆 | 最大块 | 启动耗时 |
|---|---|---|---|
| baseline | 82.3 KB | 80.0 KB | 1075 ms |
| bt | 61.8 KB | 60.0 KB | 1076 ms |
| wifi（SoftAP 起，BT 内存已释放） | 92.3 KB | 92.0 KB | 857 ms |
| both | 3.7 KB | 3.6 KB | 1261 ms |

- 按库静态 DRAM 差（baseline→bt，`esp_idf_size --archives`）：libnet80211 10,704、libpp 4,211、lwIP 2,482、wpa_supplicant 1,715、main 1,024，合计 21,008 B，与堆降幅一致；缓冲调参改不动这部分。
- 用户决定接受 21 KB、单镜像；门槛改为负载测试（ADR-0017 §3）。调参 1–5 步的运行期堆未逐个上板（静态无差别，动态部分留到 W2 浏览器负载时再看）。
- 合入方式：W0 是探针，代码不合入；只把 `sdkconfig.defaults` 两项（SoftAP、HTTPD WS；不开软件共存）和本报告合到 main，W1 在 main 上正式实现。
