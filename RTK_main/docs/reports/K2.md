## 2. 续接审计发现与修复说明

1. **短写与写入错误必须关闭受影响连接（ADR-0011 §4.4）**：
   - 原 `components/spp_server/spp_server_tx.c` 中，`spp_server_handle_write` 在 `!success`（`status != ESP_SPP_SUCCESS` 或 `len != item->len` 短写）时仅推进环头并退队，未置位 `session->disconnect_pending = true`；`spp_server_worker_submit` 在 `esp_spp_write` 同步返回非 `ESP_OK` 时亦然。若后续尾部切片留在环中继续提交，会导致向对端发送截断后残余字节。
   - 已修复：两处错误路径在匹配活跃且同 `generation` 会话时均置位 `session->disconnect_pending = true` 并唤醒 `disconnect_process`；同时在 `spp_server_write_chunk` 的预留等待循环增加 `!session->disconnect_pending` 判断，并在匿名写失败路径核对 `session->generation == item->generation`。
   - 同步更新 `tools/t13_host_check/t13_host_check.c`（`sc_write_status_propagation`、`sc_write_submit_error`）和 `tools/t13_host_check/k2_tx_check.c`（`errors()`），直接验证 1400B（5 切片）在首片失败/短写后触发断连、剩余 4 片（376B+cancel）不再调用 `esp_spp_write`、另一会话 `0x22U` 不受影响、CLOSE 后可重新打开。
2. **LinkService 信用窗口单测补齐**：
   - `test/services/test_link_credit.cpp` 原仅 1 条单测；已扩充至 5 条，覆盖并发双会话（Phone 暂停 + 白名单 Alarm 正常放行 + Phone 恢复）、角色拒绝取消信用、致命 reserve 错误断开会话、以及 legacy 无信用传输兼容分支。

- 静态内存预算：`2 * 2048B`（reply）+ `4096B`（单 PHONE stream）+ `1024B`（worker merge）= `9216B`，`push_latest` 单条最大 `40B`，无运行期动态堆分配（`g7b_check` 堆白名单 0 源文件）。
- Inflight 队列上限：`SPP_SERVER_INFLIGHT_MAX = 4U < SPP_SERVER_SDK_QUEUE_SIZE = 10U`（对应 `~/esp/esp-idf/components/bt/host/bluedroid/btc/profile/std/spp/btc_spp.c:37` `SLOT_TX_QUEUE_SIZE 10`），静态断言已生效。
- 临界区与线程安全：`spp_server_tx_commit` 与 `spp_server_worker_submit` 均在 `portMUX_TYPE` 锁外执行 payload 复制与 `esp_spp_write` 调用，依靠 `copying` / `submitting` / `users` 计数与 `generation` 防止并发 `CLOSE` 回收冲突。

## 5. 与契约的偏离与未解事项

- **与契约的偏离**：
  1. `spp_server_tx_stats_t` 未新增 ADR-0011 §9 要求的 `push_coalesced` 字段（`spp_server_push_latest` 覆盖旧推送只计入 `cancelled`）。冻结头 `components/spp_server/include/spp_server.h` 的该结构已由 K2 授权定稿，再加字段会改公共结构布局，超出“仅消除诊断、不改 ABI”的授权；作为已知偏离记录，留待 K4/K5 契约评审。
  2. tx 计数器（`accepted/completed/cancelled/errors/cong/paused/stray_write/anon_write_fail`）为 `uint32_t` 自然回绕，未实现 ADR-0011 §9 的“饱和”策略。回绕周期在实际带宽下远超设备生命周期（423 MB 级），判定可接受。
  3. 格式门禁 `clang-format` 与权威 `astyle` 冲突（§8.3），本报告按 astyle 执行。
- **未解事项**：
  1. `up256` 上行洪泛丢 15 帧（基线 8 帧），原因与 RX 方向缓冲/反压耦合，需要 K3 的 RX 窗口设计，不在 K2 范围。
  2. 高窗口（`win16`/`win32`、纯 `0x01` 下行）持续数百帧后**对端 BlueZ 侧关闭 RFCOMM 通道**（§9.5）。板端计数显示无信用泄漏，属对端/链路层行为，需在 K3 或验收环境复现定性。
  3. `clang-format` 与 `astyle` 的规则冲突需由验收方决定是否调整 `.clang-format`（当前为冻结文件）。
  4. 真实双会话（PHONE + 报警器）并发压力、短写断连恢复、GNSS `stream` 通道（K4 才实现生产者）仍需验收方在真机复测。

## 6. 复审（deepseek）发现

已逐项核对且**未发现缺陷**的点：

- 三不重叠：`ring->used`（已接纳字节）、`ring->issued`（已交 SDK）、`reserved` + `copying`（正在复制的区间）在 `reserve/commit/retire/close` 各路径下互不重复分配；`tx_close_locked` 对 `submitting` 项保留描述符与 `users` 计数直到 worker 结算，避免 CLOSE 打断在途 `esp_spp_write`。
- 迟到事件隔离：`spp_server_token_ring_locked` 同时校验 `in_use`、`generation`、`serial`、`reserved == capacity`（STREAM 另校验 `stream_owner` / `unbind`），因此 CLOSE/unbind 后抵达的 `commit` 返回 `INVALID_STATE` 且不归还新会话信用；`retire_locked` 在 `generation` 不匹配时只清在途项、不动新环。
- 回绕安全：`(int32_t)(item->order - oldest->order) < 0`、`(int32_t)(tx_done - target) >= 0` 均为无符号差再取有符号，跨 `UINT32` 回绕仍单调；`tx_total/tx_done` 只增不减。
- 每会话 ≤4 credit：`SPP_SERVER_INFLIGHT_MAX = 4 <= 4` 且 `< SDK 队列 10`（`btc_spp.c:37`），静态断言保证，全局上限即每会话上限。
- 复制在锁外：`spp_server_tx_commit` 的 4096B 复制与 `worker_submit` 的 1024B merge 复制都在 `taskEXIT_CRITICAL` 之后，单段临界区只做索引与 ≤1KiB 的有界复制。
- 反压不丢唤醒：`TX_SPACE` 为水平状态（`tx_space` 标志 + `poll_tx_space`），`wait()` 睡眠前对暂停会话复核 `reply_ready()`，`resume()` 是“检查→准备等待→再检查”结构。

回归测试覆盖（`tools/t13_host_check/k2_tx_check.c`，9 个独立进程场景）复核确认已覆盖：窗口满/CONG/预留/取消（`capacity`）、4096B 整条与 1024B 分块 + 双会话公平 + 环头回绕（`stream_order`）、`submitting` 期间 CLOSE/重开与旧 `generation` 迟到 WRITE 计 `stray_write`（`early_close`）、匿名 `NO_CONNECTION`/`NO_RESOURCE` 断开候选与无候选只计数（`anonymous`）、短写与提交失败不重发尾部（`short` / `submit_error` / `failure`）、`--wrap=memcpy` 门闩下 CLOSE 与 unbind 两条复制路径（`copy_close` / `copy_unbind`）。新修复属并发可见性与编译期断言，无法用现有替身直接观察，故未新增测试，仅由既有 9 个场景与 ASan/UBSan 全绿覆盖。

### 10.1 §9.5 “win16 高窗口断开”结论更正：主机脚本伪象，非固件问题

- 板端在停顿时刻 `status link`：`rx=805 tx=805`、`spp_tx accepted==completed`、`inflight=0`、`werr=0`，即所有请求已收到、所有应答已交给 RFCOMM。
