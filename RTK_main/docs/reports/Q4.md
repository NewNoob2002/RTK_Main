工具限制（影响覆盖，不是代码问题）：

1. 技能 `style_gate.py` 的 CLI 无法加载本仓库配置：`--mode strict`（manifest version 1 + `style: project`）下的 `verify_tidy` 报
   `.clang-tidy: unknown check option 'hicpp-signed-bitwise.IgnorePositiveIntegerLiterals' [-verify-config]` → `CONFIG_ERROR`。
   该脚本只容忍「移除 hicpp-signed-bitwise 检查名」，不容忍该检查的选项。故本报告改用其导出的 `check_docs()` 做 DOC-001 的 AST 交叉验证；`verify_tidy` 结论改由 `tools/tidy_check`（本仓库门禁）提供。
2. 用本机 clang 解析 ESP 侧 TU 需要两处修正：剔除 GCC 专有 `-Wno-old-style-declaration`，追加 `-Wno-extern-c-compat`
   （否则 `esp_libc/platform_include/sys/reent.h:31` 的 `-Werror,-Wextern-c-compat` 直接失败）。12 个 ESP 侧 TU 的失败原因全部是这条，修正后 84/84 通过。
3. 两套 Doxygen 工具口径不同，数字不可直接相减：`doc_check` 按「函数」统计且只在其扫描集内（1293 个）；技能 `check_docs` 对每个 TU 的 AST 报告函数、方法、析构、类/结构体定义，同一头文件被多个 TU 引入后行号相同即去重（1620 条）。两者在「结论」上一致：DOC-001 大面积缺失。
