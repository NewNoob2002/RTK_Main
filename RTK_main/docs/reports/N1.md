## 2. 契约说明与设计确认

1. **`DeviceService` 的 `product` 与 `board` 字段（目标 3）**：
   - `components/link_core/include/core/services/DeviceService.hpp` 在冻结清单中，已提供可写视图 `DeviceInfo &info() noexcept`。`main/modules/bt_link/BtLinkModule.cpp::init()` 直接调用 `deviceService.info().product.assign(board::productName(ctx().boardProfile))` 注入产品名，`link_core` 不依赖 `main/board`。
   - `components/link_core/services/DeviceService.cpp:214` 构造函数默认值仍保留 `"E1-Lite"`：原因有二——冻结头 `DeviceService.hpp:16` 的 Doxygen 契约显式声明默认 `product="E1-Lite"`，且 `test/services/TestServicesGolden.cpp:384` 将 `DeviceService` 默认构造输出与冻结参考实现 `reference/cpp-v3-dispatcher/command_dispatcher.cpp:419` 逐字节比对。运行期 `BtLinkModule::init()` 会在接收任何手机命令前覆盖 `info_.product`，因此线上 `0x01` 应答恒为板型产品名（`"P2"` / `"E1"` / `"RTK"`）。若 Architect 后续希望连构造默认值也改为 `"RTK"`，需同步更新冻结头 `DeviceService.hpp` 与 `TestServicesGolden.cpp`（见 §5）。
   - `board` 字段保持现状：`main/modules/bt_link/BtLinkGnss.cpp:91-93` 已在 GNSS 探测到有效型号时执行 `deviceInfo.board.assign(::gnss::modelName(gnssSt.model))`（例如 `"UM980"`、`"CM680"` 等），同时在 `94-96` 行同步 `boardFw`；未探测完成或 `RTK_GNSS_ENABLED=0` 时保持 `DeviceService` 默认 `"UM980"`。
2. **Wi-Fi SoftAP SSID（目标 4）**：
   - 当前基线 `56d022c` 尚未合入 W1/W2 代码。已核对 `ADR-0017 §2.3` 与 `SystemModule::prepare()`：设备名唯一发布点为 `AppContext::data.systemStatus` 中的 `SystemStatus::deviceName`（由 `buildDeviceName()` 写入 `<product>-<SN>`），BT SPP 初始化与控制台 `status`/`bt`/`config` 均取该字段；W2 实现 SoftAP 时直接读取同一 `SystemStatus::deviceName` 即可自动沿用 `<product>-<SN>`。
3. **启动横幅说明**：
   - `main/app/BootFlow.cpp:119` 仍打印 `"E1-Lite RTK_main %.*s"`（紧随第 121 行 `"board %s, console profile %s"`）。因任务卡未要求修改启动横幅，本次保持不动；如需同步替换，建议 Architect 决策并在后续微调。
