## 1. 核心改动摘要

### 1.1 `spp_server` RX 唤醒（level + edge）与观测快照
- `components/spp_server/include/spp_server.h`（按 `K3-dispatch.md` 授权修改并更新 `docs/frozen.sha256`）：
  - 新增 `spp_server_rx_session_stats_t`、`spp_server_rx_stats_t`、`spp_server_rx_wake_fn`。
  - 新增 `spp_server_set_rx_wake_hook`、`spp_server_rx_ready`、`spp_server_any_rx_ready`、`spp_server_rx_stats`。
- `components/spp_server/private_include/spp_server_priv.h`、`spp_server_rx.c`、`spp_server_session.c`、`spp_server_tx.c`、`spp_server_init.c`：
  - `spp_server_handle_data` 写入 `session->rx` 后离开 `s_spp_mux` 再调用 `spp_server_notify_rx_wake()`；不在临界区内调用 FreeRTOS 通知或 StreamBuffer 查询。
  - 新增 `spp_server_poll_rx_level()`：当 `evt_queue` 满导致 `DATA` / `RX_DROP` 边沿事件丢失时，靠 `rx_data_missed` 与 `rx_dropped > 0` 水平状态在 `spp_server_poll_event()` 中补发事件，避免睡死。
  - 按槽记录 `rx_high_water`、`rx_dropped_total`、`rx_events`、`drop_events` 与全局 `rx_wake_calls`。

### 1.2 RTCM 直推 `RtcmPipe` 与零批缓存路径
- `main/modules/bt_link/bt_link_module.{hpp,cpp}`：
  - 彻底移除 `SessionSink`（K2 2×1029B payload + 2×171 描述符）与 `rtcm_batch_`（2314B）。
  - `SessionDemux` 回调直接校验 `PHONE` 角色并整帧推入 `context_.rtcm_pipe.push(frame)`；满或非 `PHONE` 整帧拒绝/丢弃并累加快照计数；同步重放剩余完整帧。
  - 新增 `BtLinkModule::rtcm_snapshot()` 供 `RtcmModule` 只读抓取累计快照并管理 `reset_epoch_`（`BtLinkModule` 不反向调用 `RtcmModule`）。
- `main/def/rtcm_def.hpp`、`main/data/app_data.{hpp,cpp}`：移除 `kRtcmBatchBytes`、`RtcmBatch` 与 `DataCenter::rtcm_batch`。
- `main/modules/rtcm/{rtcm_forwarder.hpp,rtcm_module.hpp,rtcm_module.cpp,rtcm_cmds.cpp}`：`RtcmModule` 保留统计、速率窗（1000 ms）与 `reset` 纪元差值计算；`rtcm_cmds.cpp` 保持 `rtcm:` / `stats:` 原字段与顺序兼容 `tools/hil/spp_rtcm_mix.py`，新增 `reset_epoch`、`pipe_push`、`pipe_uart` 与 `rtcm_pipe:` 观测行。

### 1.3 `kLink` RX 512B 缓冲、通知唤醒与公平调度
- `main/Kconfig.projbuild`、`main/app_config.hpp`：新增 `RTK_LINK_RX_BUF_BYTES`（范围 256..1024，默认 512）作为每会话读缓冲上限 `kLinkRxBufBytes`。
- `main/modules/bt_link/bt_link_module.{hpp,cpp}`：
  - `BtLinkModule::wait(max_ms)` 注册 `rx_wake` 钩子唤醒 `kLink` 任务：先排空事件与 level 检查，阻塞前清通知并复查 `poll_and_check_ready()`，仅无就绪状态时调用 `ulTaskNotifyTake(pdTRUE, ...)`，醒后立即二次复查。
  - 取消 1 帧/轮人为截断，保留 `rx[512]` 未消费尾切片跨轮继续投递；`LinkService` 回复信用不足或挂起时暂停该会话，`rx_cursor_` 轮转保证另一会话、命令与报警心跳不被阻塞；`kRoundBudgetMs = 20` 有界约束轮耗时。
  - `handle_close` 在 `on_close` 前记录 `LinkTrace::kCloseCancel`（`components/link_core/include/core/trace_codes.hpp` 仅追加），`main/modules/debug/trace_text.cpp` 同步登记句子模板。
- `main/def/link_def.hpp`、`main/modules/system/system_cmds.cpp`：`status` / `status link` 新增 `spp_rx_events` 与每会话 `rx_buf_N`（`used`/`hwm`/`dropped`/`ev`/`drop_ev`）。

### 1.4 `kIo` 串口部分写/0 写保持、丢弃语义与 `upwin` 压测
- `main/modules/gnss/rtcm_pipe.hpp`、`main/modules/gnss/gnss_module.{hpp,cpp}`：
  - `RtcmPipe` 扩展 `RtcmPipeIoStats`（`pending_bytes`、`paused`、`discarded_bytes`、`uart_write_errors`）与 `note_discarded`/`note_write_error`/`set_pending`/`io_stats`。
  - `GnssModule::pump_rtcm_pipe()` 增加 512B `rtcm_tx_buf_` 与 `rtcm_tx_len_`/`rtcm_tx_off_`：部分写推进偏移、0 写保持待续、`uart_write_bytes < 0` 显式丢弃并计错、断电/未探测（按 ADR-0010：`kOff`/`kFailed` 等非运行态）按策略丢弃。`GnssModule::poll()` 轮询控制在有界步进内与 GNSS RX 共享 `kIo` 回合。
- `tools/hil/spp_stress.py`：新增 `--mode upwin --window-bytes 3072`（切片等待 `WAIT_SLICE_S = 0.05`，按 280B 线上帧计窗口，仅完整有效 `0x07 0x03` 应答释放窗口，超时/坏帧不释放也不重发，`--duration` 在 `upwin` 下只重复 `upwin` 不混入 `win8`）与 `--selftest`。
