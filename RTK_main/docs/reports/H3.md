## 2. 测试用例清单（全量 31 用例）

### 2.1 `test_demux_gen`（5 用例）
1. `test_crc24q_known_and_segmented`：`demux::crc::crc24q` 与独立 `demux_test::crc24q` 对 `"123456789"` 均输出 `0xCDE703`；验证 0..9 全切分点分段累计与空 span 保持传入 `crc`。

3. `test_crc_cross_check_random_bytes`：256 字节伪随机数据上 `demux::crc` 与独立位运算实现（整段及分段）逐位一致。
4. `test_xor_and_ubx_ck`：NMEA `$GPGGA` 示例 XOR (`0x47`) 与 UBX Fletcher 校验 (`ck_a=0xFB`, `ck_b=0x10`)。

### 2.2 `test_demux_engine`（13 用例）
1. `test_uninitialized_and_constinit_globals`：`constinit` 全局 `demux::Demux`、`demux::StaticDemux` 与栈上默认实例在未 `init()` 前调用 `feed(non_empty)` / `feed({})` / `abort()` 均返回 `Error::kInvalidArg` 且 `busy() == false`；随后成功 `init()` 并正常成帧。

3. `test_feed_empty_span_and_zero_len`：已 `init` 后喂入 `{}` 或长度为 0 的 span 返回 `Error::kOk`、`busy() == false`、不触发回调。

7. `test_all_reject_resync_recovers_nested_frame`：全部候选拒绝后起点前移 1 字节重扫恢复内嵌真帧，`resyncs == 1`、`rejects == 1`、`unknown_bytes == 2`。
8. `test_contract_violations_and_overflow`：`need == 0`、`len + need > max_frame`（`<= buf_size`）、`len + need > buf_size`（16 B 后金丝雀哨兵不被踩踏）、`need == SIZE_MAX` 整数回绕防护，以及契约违规按 `kReject` 回放同首字节备选成帧。
9. `test_reentry_from_callbacks`：`on_frame`（`feed` 与 `abort` 回放）及 `on_unknown`（`feed` 与 `abort`）内调用 `feed`/`abort`/`init` 均返回 `Error::kReentry` 且不破坏后续解析状态；验证回调内调用 `reset_stats()` 安全。
10. `test_abort_busy_and_recovery`：空闲 `abort` 不增 `aborts`；半帧 `abort` 丢弃并输出未知字节；半帧内嵌套完整帧及同首字节备选在 `abort` 期间回放成帧。

## 5. 偏离、工具链发现与未解决问题

1. **测试工程对 `stream_demux` 追加 `-fno-exceptions -fno-rtti`**：`components/stream_demux/CMakeLists.txt`（冻结）本身未强制 `-fno-rtti`，而测试可执行文件按任务卡启用 `RTK_CXX_STRICT`（含 `-fno-exceptions -fno-rtti`）。在 ASan/UBSan 构建中，若 `demux.cpp` 带 RTTI 编译而测试 `Sink` 子类无 RTTI，`demux.cpp` 中的 `-fsanitize=vptr` 会在虚调用 `sink->on_frame`/`on_unknown` 时误报 `object has invalid vptr`。`test/stream_demux/CMakeLists.txt` 参照 `test/host/CMakeLists.txt` 对 `rtk_pure` 的做法，为 `stream_demux` 目标统一加上 `-fno-exceptions -fno-rtti`，使组件与测试匹配目标固件 ABI（CPP-001/002），消除误报。
2. **冻结头 `static_demux.hpp:65` 与 GCC 16 `-fsanitize=undefined` 的交互（需提请架构方注意）**：
   - 现象：当使用多个跨头文件 `inline constexpr` 解码器实例化 `StaticDemux` 并调用第 2 个（及之后）解码器的 `index_of`（例如 `demux::StaticDemux<rtk::proto::demux_frame::kDecoder, demux::rtcm3::kDecoder>::index_of<demux::rtcm3::kDecoder>()`）时，在 `g++ 16.2.1 -std=c++20 -fsanitize=undefined` 下编译失败：
     `components/stream_demux/include/demux/static_demux.hpp:65:28: error: '((& demux::rtcm3::kDecoder) == (& rtk::proto::demux_frame::kDecoder))' is not a constant expression`。
   - 原因：GCC 的常量求值器在 `-fsanitize=undefined`（`-fsanitize=null`）下拒绝将两个不同 `inline constexpr` 外部/vague-linkage 变量的地址相等性比较折叠为常量表达式（普通 `g++`、`arm-none-eabi-g++` 与 `clang++ -fsanitize=address,undefined` 均可正常编译；内部链接 `constexpr` 变量在 GCC UBSan 下也正常）。
   - 最小复现：
     ```cpp
     #include "demux/decoders/rtcm3.hpp"
     #include "demux/static_demux.hpp"
     #include "rtk/proto/demux_frame.hpp"
     using Bt = demux::StaticDemux<rtk::proto::demux_frame::kDecoder, demux::rtcm3::kDecoder>;
     static_assert(Bt::index_of<demux::rtcm3::kDecoder>() == 1U); // g++ 16 -fsanitize=undefined 报错
     ```
   - 当前处理：不修改冻结头 `static_demux.hpp`。`StaticDemux::index_of` 的多索引（0/1/7）覆盖已在 `test_demux_engine.cpp` 中通过内部链接描述符完成编译期与运行期双校验；`test_demux_stream.cpp` 中 `BtStaticDemux` 在编译期校验首项 `index_of<rtk::proto::demux_frame::kDecoder>() == 0U` 并在运行期校验 RTCM3 回调下标 `== 1U`。若后续架构方需在 GCC UBSan 下支持跨 TU `inline constexpr` 描述符的 `index_of`，可在 `static_demux.hpp:65` 将 `(&D == &Ds)` 替换为 `std::is_same_v<std::integral_constant<const Decoder *, &D>, std::integral_constant<const Decoder *, &Ds>>`（已验证在 `g++ 16 -fsanitize=undefined` 下通过）。
