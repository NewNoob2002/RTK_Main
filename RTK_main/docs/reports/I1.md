## 实现与边界

### 会话与调度

- 每会话挂载 `{产品帧, RTCM3}`，产品帧优先，分流器帧缓冲 1029 B。OPEN 显式 init 并检查返回值；失败记 ESP_LOGE，该会话不喂分流器。feed/abort 的 Error 也均处理。
- 分流器回放可能在一次单字节 feed 内输出多帧。若直接在每次回调中同步调用 LinkService，会突破“一轮一个产品帧”的调度要求。因此 Sink 将该次回放的完整帧复制到静态待分发存储，由同一个链路任务按原顺序分发；处理一个产品帧即让出，下一轮先处理待分发帧，再喂新字节。角色检查发生在实际分发 RTCM 时，保留前面产品帧可能改变角色的顺序语义。
- 待分发线路字节容量为 1029 B；元数据槽数为 `1029 / 6 = 171`，6 B 是最短 RTCM 线路帧。单次单字节 feed 的全部回放输出总量不超过分流缓冲区，且下一次 feed 前排空待分发存储，故容量有界。运行时仍检查描述符与容量，异常时记错误并停止该会话继续 feed。
- 这是 ADR-0006 的内部实现补充：为保留严格调度，完整帧回调与 LinkService 分发之间增加有界复制；未改变组件接口、帧内容或角色规则。该额外存储及成本见资源证据。
- CLOSE 先释放 LinkService 槽位，再分发已有待处理帧、abort 分流器、分发回放结果并释放 main 槽。关闭后产品帧不会触发传输写，RTCM 以 kNone 角色计拒绝。半帧产生的 unknown/reject 计入归档统计，重复 CLOSE 不重复累计。

### RTCM 与快照

- Forwarder 只接受分流器已校验的完整线路帧。非 PHONE 只增加 rejected_role；不会改变 frames、bytes、crc32 或 last_msg。
- CRC 使用 `rtk::proto::crc32(wire, previous_crc)`，按实际接受顺序累计全部 RTCM 线路字节，包含 RTCM 头和 CRC-24Q 尾。
- 消息号取载荷前 12 bit。封装合法但载荷不足 2 B 时 last_msg 置 0，避免将 CRC 字节当消息号。
- unknown/product_rejects/rtcm_rejects 汇总活动会话及已关闭会话的归档值。坏产品 CRC/长度在分流器拒绝，不到达 FrameParser；新增测试验证对应 parser 错误计数仍为 0。
- `rtcm reset` 经命令队列由链路任务清零上述 8 个字段：Forwarder、活动分流器统计及归档统计一起清零，不重建分流器，不丢半帧、待分发帧或预读字节，也不清除已有 LinkService 统计。

控制台固定输出为：

```text
rtcm: frames=<u32> bytes=<u32> crc32=0x<08X> last_msg=<u16> rejected_role=<u32> unknown_bytes=<u32> product_rejects=<u32> rtcm_rejects=<u32>
```

CRC 用 `%08` + PRIX32，十六进制大写。所有跨任务查询仍通过 portMUX 保护的 StatusSnapshot。

### 新增用例

两种 Kconfig 策略下均使用实际 `policy_from_config()` 测试新场景；原有场景保持原有显式策略设定。

1. `rtcm_mix`：一次 DATA 中“产品查询 0x01 + RTCM 1005 + RTCM 1077 + 4 B 垃圾 + 产品查询 0x02”。第一轮一条应答，第二轮第二条；捕获应答并验证完整帧 CRC、消息号、sender/type、写回句柄。RTCM frames=2，bytes/累计 crc32/last_msg=1077 与独立 oracle 一致，unknown=4，rx_dropped=0。
2. `rtcm_roles`：ALARM、PENDING、主动断开至物理 CLOSE 之间的 NONE 均拒绝 RTCM；accepted frames/bytes/crc32 不变。两策略分别验证。
3. `rtcm_replay_budget`：坏 CRC 的外层 RTCM 包住“产品帧 + 有效 RTCM + 产品帧”，同一次 feed 回放出三帧；两条应答仍分两轮，RTCM 内容累计一致，外层拒绝与 6 B unknown 正确。
4. `rtcm_reset_lifecycle`：坏产品长度、坏产品 CRC、坏 RTCM 保留位均被分流器拒绝；parser 错误仍为 0。半帧时提交 reset，确认 8 项指标清零且半帧完成后线路 CRC 正确；CLOSE abort、重复 CLOSE、槽位复用、归档统计及再次 reset 均核对。
5. `rtcm_byte_budget`：最大 1029 B RTCM 紧跟另一条 RTCM；每轮实际消费字节数 <=256，半帧跨轮保留，两帧均统计且没有产品写回。RTCM 不占“一轮一个产品帧”限额。

RTCM 生成器使用独立逐位 CRC-24Q，期望累计 IEEE CRC32 也用逐位实现，不复用产品查表 CRC 作为 oracle。最终普通及 sanitizer 版本均 22/22。
