| 构建 | `rtk_main.bin` |
|---|---|
| S2（`builds/s2-b4`，GNSS on） | 800240 B |
| S3（`builds/s3`，GNSS on） | 800240 B |

与卡 §3.5 的预期“访问器删除后略减”不同，实际完全不变，原因是这些包装在目标代码里本来就不占空间：
`forModel` 的 `um982Receiver()` 与 `takeField` 都被内联（改成直取 `detail::kUm982Receiver`、`it.next(f)` 后
指令等价），4 个访问器在固件里没有调用方、早被 `-ffunction-sections` + `--gc-sections` 丢弃，只有
`test/gnss` 的 host 测试引用它们。删除只影响源码与符号表，不改镜像。
顺序说明：先构建 nognss（`-DSDKCONFIG_DEFAULTS` 带 `nognss.defaults` 覆盖根 `sdkconfig`），再删根
`sdkconfig` 用 `sdkconfig.defaults` 重建默认配置，因此 `builds/s3` 是 GNSS on、`builds/s3-nognss` 是 GNSS off，
两者与 S2 的比较口径一致（首轮构建曾反过来读到 S2 留下的 GNSS-off 根 `sdkconfig`，已作废重建）。
