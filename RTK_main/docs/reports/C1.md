# C1 分区、出厂 SN 与存储启动日志

基线为 `05821d1`。实现范围为 ADR-0014 §2.1、§2.2 和 §2.3 第 4 条。目标 profile 为 ESP-IDF 6.1、ESP32、8 MiB flash。主机测试采用内存 NVS 替身。

## 改动

| 文件 | 内容 |
| --- | --- |
| `partitions.csv`、`sdkconfig.defaults`、`main/CMakeLists.txt`、`main/app/BootFlow.cpp` | 移除 `spiffs`，新增 `nvs_fac` 和 `coredump`，打开 flash 转储，启动横幅后调用 `esp_core_dump_image_get()` 并在检测到转储时报告大小。 |
| `components/nvs_store/NvsStore.c`、`include/NvsStore.h` | 用户分区保留擦除重试，独立初始化只读状态可查询的出厂分区。SN 写入 `fac/sn`，出厂分区不可用或迁移需重试时从 `rtk/sn` 读取。读取失败清零可写输出的首字节。预留 `fac/reg` 键名和 64 字节上限。 |
| `main/modules/storage/{StorageModule.cpp,StorageModule.hpp,StoreKeys.cpp,StoreKeys.hpp,ConfigCmds.cpp}` | 启动记录两个分区的用量、SN、白名单及各目录组的恢复情况。逐组计数区分保存值、缺省与失败。每个失败键记录原始 NVS 或绑定错误名。详细键值行由启动日志和 `config` 共用。 |
| `tools/main_host_check/{CMakeLists.txt,MainHostCheck.cpp,GnssOutputCheck.cpp,shim/NvsShim.c,shim/nvs.h}` | 新增两种链路策略下的存储加载回归，复用实际 `config` handler 核对详细行。 |
| `test/nvs_store/{CMakeLists.txt,TestNvsStore.c,FakeNvs.c,FakeNvs.h,nvs.h,nvs_flash.h}` | 真实 C 组件连接两个分区的内存 NVS 替身，覆盖启动、迁移和故障路径。 |
| `docs/acceptance.md`、`tools/tidy_check/tidy_check.py` | 按用户裁定登记新主机测试套件。G5b 加载其编译数据库，覆盖检查要求其源文件都有分析任务。 |

迁移先在出厂分区记录私有键 `sn_migrating`，用来区分已有出厂 SN 和复制中断后的目标值。写入并提交 `fac/sn` 后重新读取比较，一致时才删除 `rtk/sn`。写入、提交、校验或旧键删除失败时，保留旧值供下次启动重试。旧键删除后再清理迁移标记，清理失败会记录 W，此时已核验的 SN 仍保存在出厂分区。产线显式写入 SN 时撤销未完成的迁移。

## Architect 验收（Claude，2026-11-18）

- 复核：`components/nvs_store/NvsStore.c` 迁移顺序（标记 → 写 → 读回比较 → 删旧键 → 清标记）与卡一致；只有用户分区做擦除重试。重跑 `test/nvs_store` 10/10、`tools/main_host_check` 46/46，format 通过。
- bin +20672 B 主要来自 espcoredump 组件（启用转储到 flash 的固定开销），接受。
- HIL 老板子升级（`/dev/ttyACM0`）：擦空 0xA000–0x12FFF 与 0x360000–0x37FFFF，烧 05821d1 单独构建的旧固件，`factory sn OLDSN0042` + 两条白名单；
  再用 `esptool write_flash @flash_args` 烧 `builds/c1`（含分区表）。第 1 次启动：`SN migrated to factory partition`、`SN loaded: OLDSN0042`、
  `Whitelist loaded, 2 entries`；第 2 次启动无迁移日志，SN、白名单不变；`status` wl=2；boot done 1018/1009 ms（基线约 1004–1040 ms）；无 core dump 提示。
- 教训：`idf.py -B <dir> flash` 会先按当前工作树重编该目录，旧构建目录不能当“旧固件”用；旧固件要从旧提交的 worktree 单独构建，或直接 `esptool write_flash @flash_args`。
