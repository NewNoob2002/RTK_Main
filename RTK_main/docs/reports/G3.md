严格遵循黑盒隔离原则：仅依据 `AGENTS.md`、`docs/adr/ADR-0004-stream-demux.md` 及冻结头文件（`rtk_demux.h`、`rtk_demux_decoders.h`、`rtk_proto_demux.h`、`rtk_proto_frame.h`）编写测试，未阅读 `rtk_demux.c`、`rtk_demux_decoders.c`、`rtk_proto_demux.c` 的实现源码。

## 2. 测试覆盖清单

### 2.1 `test_demux_gen`（4 用例）
1. `test_crc24q_known_vector`：CRC-24Q(`"123456789"`) == `0xCDE703` 及空指针/零长度边界。
2. `test_crc32_known_vectors`：IEEE CRC-32(`"123456789"`) == `0xCBF43926`、NovAtel CRC-32(`"123456789"`) == `0x2DFD2D88`、Unicore `#VERSION` 正文 == `0x7432D4ED`。
3. `test_xor_and_ubx_ck`：NMEA `$GPGGA` 示例 XOR `0x47` 与 UBX Fletcher 校验和。
4. `test_generators_sanity_and_bounds`：RTCM3、NMEA、UBX、Unicore 二进制、Unicore Hash（CRC-32/XOR）、产品帧的生成长度与越界拒收。

### 2.2 `test_demux_engine`（11 用例）
1. `test_init_validation_and_poison_on_fail`：`dmx/cfg/decoders/buf/on_frame` 为 NULL、`decoder_count` 为 0 或 `> 8`、`buf_size` 为 0 或小于任一解码器 `max_frame`（含第 2 个解码器）、解码器项/字段无效；失败 re-init 后实例不可用（`feed` 返回 `RTK_DEMUX_ERR_ARG`）直到再次成功 `init`。
2. `test_feed_bad_args_and_zero_len`：`feed(NULL, ...)` / `feed(dmx, NULL, 1)` / `abort(NULL)` 返回 `RTK_DEMUX_ERR_ARG`；`len == 0` 返回 `RTK_DEMUX_OK` 且不触发回调。
3. `test_idle_unknown_and_null_unknown_cb`：空闲未知字节按流顺序在帧前输出；`on_unknown == NULL` 时仅计数不崩溃。
4. `test_bulk_accumulation_and_split_chunks`：spy 解码器验证 `need` 批量累积仅在凑满时调用 `step`（整块与分段喂入均为 3 次）。
5. `test_same_first_byte_priority_and_midbuffer_replay`：3 个同首字节（`0xAA`）解码器按优先级尝试；高优先级收集 6 B 后在末尾拒绝并触发同起点回放，次优先级在 `p < len`（`p = 3` 或 `4`）成帧后，剩余字节 `buf[p..len)` 作为新输入继续拼成下一帧或输出为未知字节（`resyncs == 0`）。
6. `test_all_reject_resync_recovers_nested_frame`：全部候选拒绝后起点前移 1 字节并重扫缓冲区内嵌入的真帧，`resyncs` 计数正确。
7. `test_contract_violations_and_overflow`：`*need == 0`（`rejects++`, `overflows == 0`）、`len + *need > max_frame` 且 `<= buf_size`（`rejects++`, `overflows == 0`）、`len + *need > buf_size` 与 `*need == SIZE_MAX` 回绕防护（`rejects++`, `overflows == 1`，缓冲区后哨兵字节不被踩踏）、契约违规触发同首字节次优先级回放成帧。
8. `test_reentry_from_callbacks`：`on_frame`（`feed` 与 `abort` 回放期间）和 `on_unknown`（`feed` 与 `abort` 期间）内调用 `feed`/`abort`/`init` 均返回 `RTK_DEMUX_ERR_REENTRY`，回调返回后实例恢复可用。
9. `test_abort_busy_and_recovery`：空闲 `abort` 不增 `aborts`；半帧 `abort` 丢弃计数并清 `busy`；半帧内嵌套完整帧及同首字节备选在 `abort` 期间回放恢复。
10. `test_reset_stats_midframe_and_eight_decoders`：8 个解码器满配（覆盖 `first_mask` 位 0..7）；半帧积累期间调用 `rtk_demux_reset_stats()` 清零全部统计字段同时保持 `busy == true`，后续字节继续正确成帧。
11. `test_two_instances_independent`：两实例共享只读解码器描述符交错喂入互不干扰。

### 2.3 `test_demux_decoders`（8 用例）
1. `test_decoder_descriptors_and_first_bytes`：6 个解码器的 `name != NULL`、`proto_id`、`max_frame` 及全部 256 个字节的 `first_byte()` 精确性验证。
2. `test_rtcm3_valid_early_reject_and_crc_err`：0 载荷（6 B）、RTCM 1005 构造帧、最大 1023 载荷（1029 B，且 `step` 批量调用 `<= 4` 次）、第 2 字节保留位非 0 在 `len == 2` 早拒绝、CRC-24Q 错及坏帧后重同步恢复。
3. `test_nmea_valid_early_reject_chars_case_and_len`：标准/专有 `$P` 语句、第 2 字节 `[A-Z0-9]` 边界、大小写十六进制、可打印 ASCII 边界 `0x20`/`0x7E`、256 B 上限、257 B 超限拒绝与后句恢复、第 2 字节非法早拒绝（含 `$@`、`$`、小写等）、正文非法字符（`$`、`< 0x20`、`0x7F`、`>= 0x80`）立即拒绝、校验格式/缺 `\r\n`/XOR 错拒绝、句中嵌入 `$` 重同步恢复。
4. `test_ubx_valid_early_reject_len_and_ck_err`：0 载荷（8 B）、典型帧、最大 4088 载荷（4096 B，`step` 调用 `<= 4` 次）、第 2 字节 `!= 0x62` 早拒绝、长度超限（`4089`、`0xFFFF`）在 `len == 6` 早拒绝、CK_A/CK_B/载荷篡改拒绝及坏帧后重同步恢复。
5. `test_unicore_bin_valid_early_reject_len_and_crc_err`：0 载荷（28 B）、非零头部+载荷、最大 4068 载荷（4096 B，`step` 调用 `<= 8` 次）、第 2/3 字节（含产品帧 `0x18`）早拒绝、长度超限（`4069`、`0xFFFF`）在 `<= 24` 字节早拒绝、CRC 错及错用标准 IEEE 取反 CRC-32 拒绝。
6. `test_unicore_hash_valid_early_reject_chars_case_and_len`：真实 UM980 `#VERSION,...*7432d4ed\r\n` 向量、CRC-32 与 XOR 两种模式及大小写十六进制、`'A'/'Z'` 边界、1024 B 上限（两种模式）及 1025 B 超限、第 2 字节非 `'A'..'Z'`（含数字 `'0'..'9'`）早拒绝、正文非法字符（`#`、`$`、控制字符等）、校验长度（0/1/3/7/9 位）/非十六进制/缺 `\r\n`/错校验值拒绝、与 NMEA 合挂时 `#...$GPGGA...` 重同步恢复。
7. `test_product_demux_and_frame_view`：0 载荷、`frame_c` 已知向量、256 B 最大载荷（280 B，`step` 调用 `<= 8` 次）、第 2/3/4 字节（含 `0xB5` 与 `hdr_len != 0x14`）及 `payload_len > 256` 早拒绝、CRC 错与 NovAtel 非取反 CRC 拒绝；`rtk_proto_frame_view()` 零拷贝指针、`protocol`/`interval` 保留、非法输入不修改 `out` 哨兵、不重复校验 CRC。
8. `test_dollar_conflict_with_custom_decoder`：`$` 同首字节冲突（`rtk_demux_dec_nmea` 与自定义 `$@` 解码器，双向优先级排列，无垃圾交错 `resyncs == 0`）。

### 2.4 `test_demux_stream`（5 用例）
1. `test_property_i1_chunk_independence_1000_splits`：全部 6 个解码器同挂，混合假前导垃圾，对比整块喂入、1 字节喂入与 `1000` 轮 xorshift32 随机切分（含 0 字节、1 字节、小块与大块），断言 I1（帧序列与未知字节拼接完全一致）与 I2（字节守恒）。
2. `test_property_mixed_stream_false_preambles_recovery`：40 轮随机种子流，混合多协议随机帧与刻意插入 `D3`、`AA 44`、`AA 44 18`、`AA 44 B5`、`$`、`#`、`B5 62` 等紧贴真帧前的假前导，随机切分并 `abort`，断言所有真帧按序逐字节恢复及 I2。
3. `test_scenario_bluetooth_product_and_rtcm3`：蓝牙场景 `{rtk_proto_demux_decoder, rtk_demux_dec_rtcm3}` 交错流、I1/I2 及每条产品帧经 `rtk_proto_frame_view` 验证。
4. `test_scenario_gnss_unicore_and_ublox_sets`：Unicore 场景 `{nmea, rtcm3, unicore_bin, unicore_hash}` 与 u-blox 场景 `{nmea, rtcm3, ubx}` 交错含噪流及 I2。
5. `test_scenario_product_vs_unicore_bin_conflict`：`{rtk_proto_demux_decoder, rtk_demux_dec_unicore_bin}` 双向优先级排列无垃圾交错（`resyncs == 0`、`unknown_bytes == 0`），以及假 `AA 44` / `AA 44 99` / `AA` 前导紧跟真帧的恢复。

## 4. 与契约的偏离与未解决问题

- 无与 ADR-0004 或冻结头文件契约的偏离；G1 引擎与 G2 解码器并行产出已全部通过本套 28 个黑盒测试（含 1000+ 轮 I1 分块无关属性测试与 I2 字节守恒）。
- 开发过程中通过本测试套件自检发现并修正了测试端 3 处自我假设误差：`test_demux_gen.c` 手算 UBX `ck_b` 笔误（`0xE9` → `0x10`）、`test_demux_engine.c` 中 `p0` 需 6 B 才拒导致 4 B 尾部仍处于 `busy` 的用例构造、`test_demux_decoders.c` 对 3 字节同步头的 `step` 最低调用次数估算（`<= 4` 改为合理的 `<= 8`）。未放宽任何协议/引擎语义断言。
- 未解决问题：无。上板烧录、硬件串口实测与 `idf.py build`（G4 集成验收项）不在本任务范围。
