# OL5 OLED 帧率优化

基线为 `9ad775a`，工作分支为 `feat/ol2-oled-ui`。本次提交一并包含 Claude 的两处 OL4 HIL 修复，Web 状态仅在定位有效时上报水平精度，电源状态仅在 USB 存在时报告充电。下文的 OLED 体积对比在基线和候选两侧都包含这两处修复。

## 原因与调度

任务卡记录的 OL4 HIL 数据为 400 kHz I2C、整屏 I2C 最大 28.5 ms、总帧最大 37 ms、连按时 `oled` 报告 6.5–16 fps（约 13 fps）。连按的典型总帧为 12–25 ms。基线代码已用帧耗时扣减相对等待，因此仅用典型 I2C 耗时解释不了约 13 fps。基线的 `fps` 只统计有脏页且完整写出的帧，分母涵盖 300 ms 单击消歧等待、动画之间的静止时间，以及定点动画变化未达到一个像素的轮次。

基线还有可复现的节拍问题。相对等待从每轮重新计算，提前通知可以重设下一帧起点。超出帧预算时，旧逻辑固定再等 1 ms，后续轮次沿用延迟后的相位。虚拟时钟回归覆盖提前 5 ms 唤醒、错过一个节拍、32-bit 毫秒回绕及双击在 299/300 ms 的边界。OLED 任务现在在每 100 ms 分配 3 个绝对槽（34/33/33 ms），越过的槽跳过。单击按独立截止处理，关机/软件重启可立即出帧。动画结束后绘完最后一帧即转入事件等待。子页超时、按住覆盖层、慢速充电脉冲和需要显示秒数的页保留各自有限截止。已有 kLink 轮询合并显示数据变化，普通快照通知最多 5 次/s，稳定数据不触发刷新。

## I2C 与渲染

- 首末变化的 16 列组确定每页发送区间，组内偶尔包含相同列。每组存 32-bit FNV-1a 摘要，接受摘要碰撞的小概率以保留唯一 1 KB 帧缓冲。失败页失效后整页补写，保留此前成功的页。
- 一页发送一次 Co 控制字节序列和数据，列地址加 2。400 kHz、逐页加锁及原 8 ms 超时传参预算继续适用。满页含地址的理想线时约 3.06 ms，整帧连续持锁约 24.48 ms，超过页预算，故每页立即释锁。ESP-IDF 同步事务会阻塞等待 IRQ/信号量，驱动内部超时和错误恢复的实板最大持锁时间待测。[SH1106 数据手册 Figure 7](https://www.sino-lcd.com/upload/default/20231213/845d5fa7135c349d3be244fecf4c41ec.pdf)
- 子页转场分两段，旧内容从固定顶栏下收起，新内容推入。每帧只绘制一个内容页，顶栏在转场中复用。开机视差保留，覆盖区域改为按列清零。表盘仍显示可见卫星数，卫星柱图和 Top-8 排序仅在卫星子页及其转场中执行。
- `oled` 报告最近 2 s 成功写屏帧率和唤醒率（250 ms 分桶）、帧间隔、含控制和命令的事务字节数、渲染时间及单核 CPU 估算。`oled bench <seconds>` 在正常模式循环表盘 ↔ 电源页，报告整段计数与平均字节数，期间暂停 OLED 自身日志。关机和重启会中止 bench。`sys tasks` 增加 `oled_cpu_pct`，栈余量仍以字节显示。

## 主机与实板对照

| 样本 | OL4 基线 | OL5 |
| --- | --- | --- |
| 稳定表盘 | 约 5 次/s 定时检查，0 I2C | 虚拟任务进入永久通知等待，0 I2C |
| 单数字变化 | 1 整页，2 笔，133 B | 1 列组，1 笔，23 B |
| 强制满帧 | 16 笔，1064 B | 8 笔，1080 B，8 个独立持锁区间 |
| 模拟器表盘 → 电源页，4800–5220 ms | 13 个变化帧，140 笔，9310 B | 13 个变化帧，55 笔，7041 B，全程 0 次顶栏变化 |
| 模拟器电源页 → 表盘，5600–6020 ms | 13 个变化帧，138 笔，9177 B | 13 个变化帧，55 笔，7281 B，全程 0 次顶栏变化 |
| 虚拟 400 kHz bench，1 s | 任务卡记录约 13 fps 的实板连按样本，工作负载不同 | 30 次完整写屏，31 次唤醒，16476 B，549 B/帧，最大间隔 34 ms，0 错误 |

字节数含控制和命令，未计 I2C 从机地址。模拟器事务数来自相邻 PBM 帧对比，按旧整页与新 16 列分组分别计算。两端静止页面逐像素一致。原始帧与对比图在本地构建目录内。 [模拟器截图对比](../../builds/ol13-oled-comparison.png)

`cpu_pct` 用 `esp_timer` 累计 OLED 每轮墙钟工作时长，扣除同步 I2C/互斥锁阻塞区间，包含渲染、快照、摘要和封包。高优先级抢占可能让墙钟估算偏高，I2C API 区间内的驱动 CPU 工作未单列。到达 30 fps 且单核 CPU ≤10% 要求平均非阻塞工作量 ≤3.33 ms/帧。以渲染 2.5 ms、其余工作 0.5 ms 为预算情形，估算单核约 9%。若渲染每帧都接近 4 ms，即使无其他开销也会到 12%。旧 `frame_us - i2c_us` 约 8 ms 还包含快照、渲染外逻辑及抢占，无法直接视为渲染成本。已移除原来每帧绘制双页、重复顶栏、逐图元清除大片覆盖区域的工作，实际 `render_us max` 需独立验收。

板上由用户比较 `oled bench 10`、`oled` 与 `sys tasks`。动画预计接近 30 fps，验收线为动画 ≥25 fps、整屏转场 ≥20 fps、单核 CPU ≤10%、单帧渲染 ≤4 ms。需同时复核 OLED 栈余量、真实 I2C 持锁及业务负载下的掉帧。当前没有 OL5 实板结论。

## 体积

ESP-IDF v6.1、ESP32、相同 `sdkconfig`，用 `idf.py build` 和 `idf.py size` 对比工作树与基线副本。基线副本由 `git archive 9ad775a` 得到，并应用同一份 Web / Power 修复。基线和候选分别在 `builds/ol13-size-baseline` 与 `builds/ol13-idf`。

| Flash code | 1,132,836 B | 1,136,972 B | +4,136 B |
| Flash data | 274,252 B | 274,572 B | +320 B |
