# D1 控制台构建档位

D1 已实现，基线为 `dd00492`。使用 ESP-IDF v6.1 构建，完整离线门禁 33 项全部通过。PRODUCTION 固件保留诊断和隐藏工厂命令，NONE 固件保留 UART0 日志直写路径，REPL 和 linenoise 已从 ELF 裁掉。P2 台架验收和启动后空闲堆待 Architect 测量。

## 整改

AGY 对 `b4d5488` 提出的 3 项应改和 2 项建议均已在 `feat/d1-console-profile` 工作区处理。

| 评审项 | 处理 | 验证证据 |
|---|---|---|
| 应改-1 | `config build` 使用 `cli::printKv` 输出独立的 `console_profile` 键。 | PASS。两种链路策略的 `storage_startup` 用真实命令处理器捕获输出，断言 `[build]` 下的 UART 行与档位行各自按键值格式显示。 |
| 应改-2 | 为 PRODUCTION 增加 GNSS 开启、trace 分别开关的动词组断言，并为 DEV 增加 GNSS 与 trace 均关闭的断言。 | PASS。主机编译期断言验证各组合的完整动词组及顺序。 |
| 应改-3 | 在生产步骤表上注入 `power`、`console` 与 `alloc` 故障。用已执行记录的名称判定是否到达 console，覆盖 console 步自身失败。 | PASS。`boot_steps` 对 DEV、PRODUCTION 验证早期 Init 成功时顺序为 Init → Attach → Run，失败时只调用 Init，已到达 console 时顺序为 Attach → Run。NONE 在全部注入场景中均为零次调用。 |
| 建议-1 | 命令登记使用 `constexpr` 提供函数指针表，表内任一命令启用时才取表，再按名字登记。空串不匹配，禁用动词组的提供函数、名称和摘要均为 `nullptr`。 | PASS。按 PRODUCTION 编译数据库以 `-O0` 另编 `ConsoleSetup.cpp`，用 `xtensa-esp32-elf-nm -C --undefined-only` 与 `strings` 验证禁用表引用和摘要已经裁掉。最终 PRODUCTION 与 NONE ELF 均通过符号复查。 |
| 建议-2 | 将 `console_profile_check` 按 DEV 默认回退、显式 PRODUCTION、显式 NONE 编译三次，并采用与 `board_profile_check` 一致的异常、RTTI 和告警选项。 | PASS。三个目标分别断言枚举与档位字符串，普通和 ASan/UBSan 的 `main_host_check` 各 63/63。 |
