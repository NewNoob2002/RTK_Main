## 2. 文档与现有代码不一致之处（以代码为准）

按任务要求对照 `docs/CODING-STYLE.md`、`docs/adr/ADR-0008-code-organization.md` 与实际源码，发现以下 4 处差异并在 `main/modules/_template/README.md` 中按代码现状写明：
1. **`MODULE_DEF` 签名与控制台集中注册**（`docs/CODING-STYLE.md` §1.3 vs `main/module_list.inc` / `main/app_main.cpp`）：§1.3 示例写成 2 参数 `MODULE_DEF(BtLink, kLink)` 且只提“在 `module_list.inc` 增删”；实际代码 `main/module_list.inc` 为 6 参数 `MODULE_DEF(类型, 成员, 名称, ModuleKind, ExecKind, poll_period_ms)`，且 `main/app_main.cpp` 的 `start_console()` 以定长 `std::array<std::span<const rtk::console::Cmd>, N> cmd_tables` 注册命令表，新增带命令的模块须同步递增 `N` 并追加 `<name>_cmds()`（`app_main.cpp` 已通过 `app_context.hpp` → `module_list.inc` 间接包含模块头）。
2. **`ModuleKind` 预留项顺序**（`main/app_config.hpp` vs `main/module_list.inc`）：`app_config.hpp:23` 的 `ModuleKind` 末尾已有 `kSystemMode`，当前 `module_list.inc` 尚未登记对应模块；按注释“枚举顺序即 ID，勿插入或重排”，新模块枚举只能追加到 `kSystemMode` 之后。
3. **`StoreKey` 尚未被 `StorageModule` 自动扫描**（`components/app_fw/include/rtk/fw/store_key.hpp` vs `main/modules/storage/storage_module.cpp`）：`StoreKey` 与 `valid()`/`unique_keys()` 已就绪，但现行 `StorageModule` 仍直接调用 `components/rtk_store` 的 C 接口读写，并未自动遍历各模块 `kKeys[]`；`README.md` §9 已明确提醒需同时扩展 `rtk_store` 与接入调用。
4. **`system_module` 文件头执行器名笔误**：`system_module.hpp:1` / `system_module.cpp:1` 原误写 `kSystem`，实际 `ExecKind` 只有 `kLink`，本次已修复。
