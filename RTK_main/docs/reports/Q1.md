## 2. A 类：代码违反本工程自己的规则

### 必须修复

**Q1-A01** `components/cli` 依赖自有组件 `app_fw`，违反 AGENTS.md §3 的 cli 禁止列，也与本组件 CMakeLists 的自述矛盾。

- 证据：`components/cli/CMakeLists.txt:8` `REQUIRES console esp_system esp_driver_uart app_fw`；同文件第 2–4 行注释写
  「只依赖 IDF（console、esp_system、串口驱动），不依赖任何自有业务组件（含 app_fw）」；
  `components/cli/src/Console.cpp:19` `#include "fw/Log.hpp"`。
- 规则：AGENTS.md §3 `components/cli` 行「禁止：其他自有组件（保持报警器可复用）」。
- 机制确认：技能 `arch_lint.py` 用自建层表（`cli`→`components/cli`、`module`→ 六个纯组件）报同一条
  `components/cli/src/Console.cpp:19: [layer_dependency] cli -> module via "fw/Log.hpp"`，是全仓唯一一条越层。
- 建议：见待决提议 P1（把 `app_fw` 定性为框架基座并写进 cli 的可依赖列，或把日志门面下移到 IDF 侧薄封装）。

**Q1-A02** `components/nvs_store` 依赖自有组件 `app_fw`，违反 AGENTS.md §3 的 nvs_store 禁止列；同时 AGENTS.md §2 又要求
C 组件用 `fw/LogC.h`，两条规则自相矛盾，实现方无论怎么做都违规。

- 证据：`components/nvs_store/CMakeLists.txt:6` `REQUIRES nvs_flash log app_fw`（注释「只依赖 IDF 的 nvs_flash/log」）；
  `components/nvs_store/NvsStore.c:9` `#include "fw/LogC.h"`，`FW_CLOGW(FW_LOG_CAT_STORE, …)`、`FW_CLOGE(…)`。
- 规则：AGENTS.md §3 nvs_store 行「禁止：其他自有组件」vs AGENTS.md §2「C 用 `fw/LogC.h` 的 `FW_CLOG*`」。
- 建议：见待决提议 P1。

**Q1-A07** `components/gnss/src/Registry.cpp` 的驱动地址表是函数内静态，带动态初始化与 `__cxa_guard_*`，与自己的注释和
`constinit` 规则相反。

- 证据：`components/gnss/src/Registry.cpp:48` `std::span<const Receiver *const> enabled_receivers() noexcept {`，
  注释写「地址表：accessor 不是 constexpr 函数，故用 const 静态表（地址为常量，仍是常量初始化）」，
  但其后 `static const std::array<const Receiver *, kEnabledCount> kList{ … }` 经宏展开依赖 `&unicore_receiver()` 调用；
  `xtensa-esp32-elf-nm -C builds/p3c/esp-idf/gnss/CMakeFiles/__idf_gnss.dir/src/Registry.cpp.obj` 给出
  `b guard variable for gnss::enabled_receivers()::kList` 与 `b gnss::enabled_receivers()::kList`（.bss，动态初始化），
  且该目标文件是唯一引用 `__cxa_guard_acquire/__cxa_guard_release` 的自有目标文件（77 个自有 .o 全扫过）。
- 规则：CODING-STYLE §4.4「全局对象 `constinit`」、技能 CPP-009/CPP-010；注释与实际不符本身也违反 §2「注释解释原因」。
- 建议：见待决提议 P2（把 accessor 改成返回引用的 `constexpr` 表，或首次 `init()` 时一次性构造并留出显式状态）。

**Q1-A08** 静态分析门禁红：`main/def/GnssDef.hpp:108` 魔数。

- 证据：`tools/tidy_check/tidy_check.py --host-build builds/q1-host --idf-build builds/p3c --test-app-build builds/rtk_pure-esp32`
  → `main/def/GnssDef.hpp:108:26: error: 6U is a magic number; consider replacing it with a named constant [readability-magic-numbers,-warnings-as-errors]`。
- 规则：AGENTS.md §3「`.clang-tidy` 为 `WarningsAsErrors: '*'`，LSP 中出现的告警与构建同等对待」、CODING-STYLE §5.2「用具名常量」。

## 5. 待决提议（需架构方决定，本轮不改代码与规则文本）

**P1 自有组件的「框架基座」定性（关联 Q1-A01/A02）。**
`app_fw` 同时被 `cli` 与 `nvs_store` 依赖，而 AGENTS §3 对这两个组件写的是「禁止其他自有组件」，§2 又强制 C 组件用 `fw/LogC.h`。
建议二选一：(a) 在 §3 把 `app_fw` 明确为「框架基座，任何组件可依赖」（最省事，与现状一致，也让报警器复用 `cli` 时同样需要
`app_fw` 的错误码与日志）；(b) 把 `fw/LogC.h`/`fw/Status.hpp` 下沉到一个无依赖的新组件（如 `base_fw`），`cli`/`nvs_store` 只依赖它。
影响：选 (a) 只改文档一句话；选 (b) 要动 15 处 `#include "fw/Status.hpp"` 与 5 处 `fw/LogC.h`，且要重算冻结清单。

**P2 修 `gnss::enabled_receivers()` 的静态初始化（关联 Q1-A07）。**
建议把 accessor 改成返回引用的 `constexpr` 函数（接收机对象本身就是文件作用域 `constinit` 静态实例，取地址是常量表达式），
或改成显式 `init()` 时填表 + `std::span` 缓存在 `GnssModule` 里。影响：`components/gnss/src/Registry.cpp` 一处；需重跑
`test/gnss` 与 `builds/*/rtk_main.elf` 的 `__cxa_guard` 检查（目标是把它从自有目标文件里去掉）。附带建议加一条门禁：
`g7b_check` 顺带统计自有 `.o` 的 `__cxa_guard_*` 引用，非零即 FAIL。

**P3 `static_cast` 注释规则的可执行化（关联 Q1-A03）。**
建议把 CODING-STYLE §4.5 收紧为「`static_cast` 造成窄化、符号变化、指针↔整数、或跨 ABI 类型还原时必须写明范围理由」，
