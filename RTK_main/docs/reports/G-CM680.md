# G-CM680 接收机识别

依据 ADR-0012 §2.9，基线 `98d82b3`。CM680 使用 Unicore 家族的 UM980 驱动，探测、状态和 NVS 保存独立型号 `kCm680`，数值为 `6`。

## 改动与分支追踪

| 文件或路径 | 处理 |
| --- | --- |
| `components/stream_demux/src/decoders/UnicoreHash.cpp` | CRC-32 优先按原范围计算，失败时再把首字节 `#` 纳入计算。两次都失败时用原范围的计算值报告 `kCrcChecksum`。XOR 保持原有覆盖范围。复核仅在帧尾执行。 |
| `components/gnss/src/Registry.cpp` | `modelName` 返回 `CM680`，`familyOf` 返回 `kUnicore`，`modelFromU8` 接受 `6`。 |

| `main` 型号消费端（核对） | GNSS 启动与状态命令、系统状态、trace、`config` 均通过注册表显示型号。`gnss.cache` 的 `model` 以 U8 保存，范围 0–255，读回使用 `modelFromU8`。 |

| `test/fixtures/Cm680Version.hpp`、`test/stream_demux/TestDemuxDecoders.cpp` | 三条实板帧保留原始 CRC 与 CRLF，逐字节送入分流器。损坏一位 CRC 时，验证拒绝计数、收到值 `0x589EA8BF` 和原范围计算值 `0x05053BD7`。 |
| `test/gnss/TestGnssRegistry.cpp`、`test/gnss/TestGnssUnicoreReceiver.cpp` | 覆盖型号名、家族、NVS 数值、固件版本文本、驱动选择和能力，验证 `CM681`、`CMX`、`CM680A` 均被拒绝。 |

## 修订 A

P2 v1.41 的实板回放复现了 `UNLOG COM1` 收到两条 ERROR 后无法进入运行态的问题。`UnicoreReceiver.cpp` 为 CM680 生成 `UNLOGALL COMn`，并通过 `outputMask` 同时过滤开启和关闭 `SATSINFOA` 的命令。GST 和现有 GSV 路径仍可用。UM980、UM981 和 UM982 沿用原脚本，既有黄金向量通过。

`TestGnssUnicoreReceiver.cpp` 对比 CM680 和 UM980 的 COM1 首步，验证 GST/GSV 能力及开启、关闭 SATSINFOA 均返回 `kNotSupported`。`GnssResetCheck.cpp` 回放实板原始双 ERROR、VERSIONA 应答和 `#VERSIONA`，其余测得状态按包含 `$` 的 XOR 生成应答。P2 主机用例断言进入 `kRunning`，并检查启动及重配期间没有发送 SATSINFOA。

## 修订 B

Architect 的第二轮 HIL 确认修订 A 可进入运行态并重探。CM680 对 GSA 的 0.1、0.2、0.5 s 命令返回 ERROR，对 1 s 返回 OK。`UnicoreReceiver.cpp` 仅在生成 CM680 GSA 命令时把大于 0 且小于 1000 ms 的周期提高到 1000 ms。0 ms 仍生成 `UNLOG`，至少 1000 ms 的周期原样传入命令生成器。App 仍使用原请求周期。

`TestGnssUnicoreReceiver.cpp` 校验 CM680 GSA 的 50/100 ms、关闭、1 s 和 2 s 指令，以及 UM980 GSA 和 CM680 GGA 的 100 ms 指令。`GnssResetCheck.cpp` 的 CM680 替身从 1 Hz 开始，对亚秒 GSA 返回 ERROR。`rate 10` 用例确认 `lastApply == kOk`、模块处于 `kRunning`、失败位为零、App GSA 计划周期为 100 ms，并从 NVS 读到 10 Hz。
