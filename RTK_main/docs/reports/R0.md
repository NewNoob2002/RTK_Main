## 4. 白名单构造验证方法

`builds/r0/verify_g7b.py` 在 `builds/r0/` 下建立 `TemporaryDirectory`：
用已有 Xtensa 编译器生成引用真实 malloc/free 的小 C 目标文件，使用实际 `nm` 检查。
临时编译数据库有意将构造对象关联到现存 `main/app_main.cpp`，用于测试源路径门禁；
这不是证明 app_main 实际分配堆，也没有改动/重编译该源文件。
临时构建引用真实构建的 ELF/map；异常 ELF 验证只在临时副本注入符号，map 验证只改临时文件。
通过 `--allowlist <临时文件>` 指定白名单副本，未更改正式白名单或真实构建对象。

| 状态 | 场景 | 预期并实际得到 |
| --- | --- | --- |
| PASS | 空白名单 + malloc/free | 退出 1，未登记 FAIL |
| PASS | 临时登记 `main/app_main.cpp # 启动期一次性；构造验证` | 退出 0，逐个列出 malloc/free 与理由 |
| PASS | 同名对象映射到另一个未登记源文件 | 退出 1，不按对象 basename 误放行 |
| PASS | 编译数据库无该对象映射 | 退出 1，源文件 UNKNOWN |
| PASS | output、arguments、command 三种映射 | 都关联到精确源文件；command 经过 shell 参数解析 |
| PASS | 损坏编译数据库 | 退出 2，明确报告无法读取数据库 |
| PASS | 无说明、越界、通配、目录、绝对路径、重复条目 | 退出 2，拒绝非法白名单 |
| PASS | 白名单文件不存在 | 退出 2，不静默豁免 |
| PASS | 已登记堆文件额外引用 `__cxa_throw` | 退出 1，自有目标异常禁令仍生效 |
| PASS | 临时 ELF 增加 `__cxa_throw` | 退出 1，全 ELF 白名单外异常符号仍拒绝 |
| PASS | 临时 map 不含原固定拉入链 | 退出 1，固定链检查仍生效 |

验证正常退出后临时对象、名单、ELF 副本和 map 均自动删除。正式名单仍为 0 条。
