# C4 恢复出厂与蓝牙配对窗口

基线 `bbc23f0`。实现依据 C4 任务卡和 ADR-0014 §2.7、§2.8。

## 实现

| 文件 | 改动 |
| --- | --- |
| `components/nvs_store/NvsStore.c`、`include/NvsStore.h` | 分别调用 IDF 的用户与出厂分区擦除 API，返回底层结果。冻结头的差异为任务卡授权的两个声明及其契约。 |
| `main/modules/storage/{StorageModule.cpp,StorageModule.hpp,StoreKeys.cpp,StoreWriteGate.hpp}` | kLink 执行器独占擦除，标量、blob、白名单、SN 和 GNSS 缓存写入都受写入门控。若已有写入在途，命令返回 busy，可重试。 |
| `main/modules/system/{FactoryReset.cpp,FactoryReset.hpp,FactoryCmds.cpp}`、`main/app/ConsoleSetup.cpp` | 注册顶层 `freset` 和解锁后的 `factory erase`。显式确认后擦除，成功记录 `Factory reset done, restarting` 并重启。失败输出 ERR 并保留当前运行会话。 |
| `components/link_core/LinkManager.cpp`、`private_include/PairWindow.hpp` | 固件为 LinkManager 绑定一个窗口。手机 0x44、控制台及工厂别名操作该窗口。GAP 和报警器 HELLO 使用同一到期点，默认关闭。独立使用冻结 LinkManager 接口时仍支持原有 60 秒流程。 |
| `components/spp_server/{SppServerGap.c,SppServerSession.c,private_include/SppServerPriv.h,boot_include/SppServerPairing.h}` | BTC 只登记 GAP 事件，worker 查询应用策略、处理确认与发出 PIN/SSP 应答。单一待确认请求最多等 30 秒。窗口关闭时用白名单判定。认证成功时通知可用 `bt trust`。发现模式沿用 `ESP_BT_GENERAL_DISCOVERABLE`。 |
| `main/modules/bt_link/{BtPairing.cpp,BtPairing.hpp,BtLinkCmds.cpp,BtLinkModule.cpp,BtLinkModule.hpp}`、`main/modules/system/SystemModule.cpp`、`main/def/LinkDef.hpp`、`main/CMakeLists.txt` | 应用将窗口和白名单快照查询注入 SPP worker。注册 `bt pair` 状态、10–600 秒开窗、关窗和确认，以及 `bt trust/untrust`。白名单操作沿用已有 kLink 持久化。 |
| `main/modules/gnss/{GnssModule.cpp,GnssModuleMaintenance.cpp}` | 用户 NVS 正常启动时，缺少波特率键则采用 Kconfig 缺省作为 C2 对齐目标。仅实际速率不同时验证、切换和保存，覆盖整机恢复出厂后的启动。 |
| `test/nvs_store/`、`tools/main_host_check/`、`tools/t13_host_check/` | 增加分区擦除隔离和故障传播、控制台确认与擦除失败、写入排他、窗口统一及超时、白名单旁路和手动确认回归。 |

普通 `freset` 擦除整个用户 NVS，出厂身份、PHY 数据、core dump 和接收机自身设置均保留。IDF 擦除会在全局锁内先关闭目标分区的所有句柄并卸载分区，Bluedroid 在重启前无法重新打开用户 NVS 写回绑定。依据为本机构建所用 ESP-IDF 的 `components/nvs_flash/src/nvs_api.cpp`，函数 `nvs_flash_erase_partition`。

`factory erase yes` 依次擦除用户和出厂分区。两个物理擦除操作分别返回结果，第二次失败时用户分区可能已清空，命令报告错误且不自动重启。确认命令需要 kLink 存储执行器处于运行状态。配对状态、手动确认和窗口时长均保存在 RAM。
