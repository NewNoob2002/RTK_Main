## 2. 关键实现说明

1. **`rtk::console::add` 与 `start`（`components/rtk_console/src/console.cpp`）**
   - `add` 在 `start` 后调用返回 `ESP_ERR_INVALID_STATE`；空表返回 `ESP_OK`。对整张表做原子预校验：任一项 `name`/`help`/`handler` 为空返回 `ESP_ERR_INVALID_ARG`；与已登记命令名重复或表内自身重名返回 `ESP_ERR_INVALID_STATE`；合计超 `kMaxCmds`（24）返回 `ESP_ERR_NO_MEM`，校验通过前不登记任何一项。
   - 按冻结头注释“只保存指针，表必须是静态存储”，内部保存 `std::span<const Cmd>` 表指针而非拷贝 `Cmd` 结构体（`librtk_console.a` 静态 DRAM 仅占 **201 B**，较拷贝 `24 * sizeof(Cmd)` 省出 284 B，使合入 J1+J2b+J3 后的总静态 DRAM 增量保持在 ADR 规定的 4 KB 门限内）。
   - `start` 复用原 `app_console.cpp` 的 REPL 参数（UART0 115200、`tx/rx_gpio_num=-1`、`max_cmdline_length=256`、`task_stack_size=4096`、`task_priority=2`、`task_core_id=0`），并按 `sdkconfig` 支持 UART / USB-CDC / USB-Serial-JTAG 分支；使用 `esp_console_cmd_t::func_w_context` 与 `context` 透传；注册或启动失败均调用 `repl->del(repl)` 清理。

2. **纯参数解析辅助（`components/rtk_console/src/parse.cpp`）**
   - 手写逐字符无符号解析代替 `strtoul`，拒绝前导空格、`+`/`-` 符号、空串、`0x` 无数字前缀、尾随字符与 32 位/8 位溢出；`parse_mac` 严格校验 `AA:BB:CC:DD:EE:FF`（17 字节、大小写均可）；`parse_hex` 先两遍校验偶数个 hex 字符且 `<= out.size()`，再写入 `out` 与 `written`，所有函数失败均不改输出参数。

3. **头文件包含顺序（`main/app_cmds.hpp`）**
   - 沿用 J1 §6 规则，在 `app_cmds.hpp` 打开 `namespace rtk::app` 之前包含 `app_ids.hpp`，确保冻结 OS 头中 `app::` 始终解析为顶层 `::app`。

## 6. 偏离与未解决问题

- 无与任务卡或 ADR-0007 的偏离。
- `alarm set` 的数字解析从 `strtol(..., 10)` 切换为 `rtk::console::parse_u8`：合法范围仍为 `state 0..2`、`level 0..3`，且非法参数（如负数、溢出、非数字后缀、空串）输出与旧实现一致；`0x` 前缀十六进制输入（如 `0x2`）现按 `parse_u8` 契约亦能被合法解析。
- 未解决问题：`rtk_console` 在 ESP32 实板上的 UART0 REPL 交互（`help` 与 7 条命令实机执行）及 `astyle_py` 权威格式门禁留待 J5 验收执行。
