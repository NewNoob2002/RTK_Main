# P1 手机协议兼容

基线 `56d022c`，实现 Codex。目标为 ESP32 与 ESP-IDF v6.1。全部构建目录使用 `builds/p1-*`。

## 实现

| 指令 | 行为 |
| --- | --- |
| `0x24` | 查询返回 16 B，前 8 B 为 IEEE 754 binary64 小端天线高（m），尾部清零。默认 0.0。设置接受有限的 0～10 m，成功回 `01 01`，短包或非法值回 `02 02`。NVS 键为 `rtk/ant_height`，沿用 500 ms 去抖及失败退避。当前板端无 IMU 驱动，天线高设置不触发倾斜对准。 |
| `0x25` | 返回 set-res，负载 `00 00`。 |
| `0x29` | 返回 set-res，负载 `01 01`。 |
| `0x33` | 查询返回 4 B，首字节为已保存的开关，尾部清零。设置接受 0 或 1，通过 `fw::Command` 交 kIo。接收机逐条确认并完成 `SAVECONFIG` 后，写入 `rtk/ppp_enable` 并回 `01 01`。NACK、超时与写入失败回 `02 02`。非 Unicore 接收机的设置请求回失败。缺键时查询为 0，接收机沿用已有配置。 |
| `0x28/0x30/0x34/0x36` | 保留无应答行为。 |

PPP 开启时依次下发 `CONFIG SBAS DISABLE`、`CONFIG SIGNALGROUP 2`、`CONFIG PPP ENABLE E6-HAS`、`CONFIG PPP CONVERGE 15 25`、`SAVECONFIG`。关闭时下发 `CONFIG PPP DISABLE`、`SAVECONFIG`，沿用旧固件的 SBAS 行为。每条命令等待匹配回显的 `$command,...,response: OK`，单步超时为 1 s。失败立即停止脚本并由 kIo 记 `FW_LOGW`，保留应用侧已保存值。接收机可能已执行失败步骤之前的命令。上电与重探测后完成接收机配置时重放有效的 NVS 值。

链路预留原会话的应答额度，配置完成后回包。断开时释放额度，接收机继续处理已受理的设置。沿用 kLink、kIo 静态任务，纯组件继续在 host 构建。

## Revision A

依据 `docs/tasks/P1-phone-compat.md` §4（2026-11-19 HIL 结论与用户决定）及旧固件 `P2_V2.7/{meaasge.ino,UM980.ino,EEPROM.ino}`，在 P1 基础上完成 Revision A。全部构建目录使用 `builds/p1a-*`。

### 1. 实现摘要

1. **按 `sender` 区分 `AppKind`**：`CommandRouter` 每帧按 `appKindFromSender(frame.sender)` 填充 `reply.appKind`（`0x00` = `kNav`，其余 = `kSurvey`），会话角色保持 `PHONE`/`ALARM` 不变。
2. **GNSS 订阅指令应答对齐（`GnssService`）**：
   - `0x04/0x21/0x22`：Nav 维持 `interval=0` 回 `query-res` 最近一句原文、`interval≠0` 回对应应答类型 `01 01`；Survey 统一回 `set-res(0x03)` `01 01`（无能力回 `02 02`），`interval` 订阅直传开关不变。
   - `0x23`：Nav 与 Survey 均回 `set-res(0x03)` `01 01`（无能力回 `02 02`），订阅逻辑不变。
   - `0x05`：Nav 回 `query-res(0x01)` 2 B `00 00`，Survey 回 `set-res(0x03)` 2 B `00 00`；具备 `#SATSINFOA` 能力时继续按 `interval` 切换订阅。
   - `0x1F`：维持原行为。
3. **PPP 硬件能力门控**：在 `components/gnss/private_include/PppSequence.hpp` 提供 `gnss::supportsPpp(Model)`（仅 `kUm980`/`kUm981`/`kUm982` 返回 `true`，`kCm680`/`kZedF9p`/`kK803`/`kUnknown` 返回 `false`，不改 `components/gnss/include/**`）。不支持时 Survey `0x33` query 回 `00 00 00 00`，set 在 `PhoneCompatService` 与 `GnssModule` 双重校验，直接同步回 `02 02` 且不发送任何串口命令、不修改 NVS；上电/重探测亦跳过 PPP 重放。
4. **通用延迟应答机制（`LinkService`）**：删除 `LinkService.cpp` 中静态全局 `s_phone_link`/`s_phone_service` 与 `bindPhoneCompat`。服务返回 `DispatchResult::kDeferred` 并提供 `DeferredHook{poll, cancel, ctx}`，由 `LinkService` 持有原会话的应答额度，`BtLinkModule::poll()` 每轮调用 `linkService().pollDeferred(now)`（`tick()` 亦调用）推送结果；会话断开或清空时自动归还额度并调用取消钩子。Survey `0x33`（PPP）与 `0x06`（截止角/星座）均复用此机制。
5. **补全旧固件消息与 NVS 持久化**：
   - 全部 14 组旧固件消息均已补齐（路由总数 37 ≤ `kMaxRoutes` 48），零堆分配、全静态缓冲。
   - 新增 5 个 `rtk/` NVS 键：`sat_cfg`（6 B）、`pn`（16 B）、`ntrip_cfg`（112 B）、`json_srv`（42 B）、`tb_cfg`（86 B），`store::kMaxBlobKeyBytes` 由 64 B 提至 128 B；`ant_height`/`pn`/`ntrip_cfg`/`json_srv`/`tb_cfg` 复用统一 500 ms 去抖 + 1–30 s 指数退避落盘逻辑；`0x08` SN 复用 `saveSn`（`nvs_store_set_sn`），`0x06` 与 `0x33` 在 GNSS 接收机逐条返回 OK 后落盘，并在 `kConfiguring`（上电/重探测）时先重放 `sat_cfg` 再重放 `ppp_enable`。
   - `GnssModule::publishAppFrame` 缓存最近单条 GSV 语句（≤256 B）供 Nav `0x0A` 查询。
   - `0x1E` 在 `BtLinkModule` 中先发送 `set-res` `01 01`，记录 250 ms 延迟并在 `wait()` 中限制最长休眠 50 ms，到期后执行 `StorageModule::kEraseUser` + `esp_restart()`（与现有 `FactoryReset.cpp` 一致）或 `esp_restart()`。
   - `0x28/0x30/0x34/0x36` 继续保持未注册（无应答）。

## Revision B

依据 `docs/tasks/P1-phone-compat.md` §5（2026-11-19 HIL 结论与用户决定）及旧固件 `P2_V2.7/GNSS.ino:312-336`，在 Revision A 基础上完成 Revision B。全部构建目录使用 `builds/p1b-*`，未改动 `sdkconfig.defaults` 及任何新增冻结头。

### 1. 实现摘要

1. **PHONE 连接即推默认 NMEA（`BtLinkModule` / `GnssModule`）**：
   - `GnssModule` 发布 `GnssStatus::supportedMask` 扩至 7 位（含 bit 6 `kGsv`，`GnssService::setSupportedMask` 内部仍只取 bit 0..5，兼容不变）；`GnssModule::publishAppFrame` 在缓存最近单句 GSV 的同时，当订阅掩码含 bit 6 时将原样 GSV 推入 App 环（不新增模块输出配置）。
   - `BtLinkModule::handleOpen()` 在新会话角色为 `Role::kPhone` 时立即调用 `onPhoneSessionOpen()` 开启默认直传：掩码为 `(GGA|GST|RMC|GSA|GSV) & supportedMask`（探测完成前按默认集回退，探测完成后 `syncGnssInfo()` 自动取交集刷新），对应周期为 0（沿用模块输出、不节流），无需等待手机发送任何请求帧。
   - `Role::kAlarm`（白名单）会话不开启默认直传；若配对窗口内未知设备先按 `kPhone` 连接后发送 `0x41` HELLO 转为 `kAlarm`，`recheckPhoneSessionRole()` 立即调用 `resetGnssStreamSession()` 关闭直传并清空环。
2. **Configure (Nav) 首帧关闭默认直传**：
   - `SessionSink::onFrame` 在派发前调用 `onPhoneProductFrame()`：当当前 PHONE 会话收到 `sender == 0x00` 帧且默认直传仍开启、未显式订阅时，立即关闭默认直传（掩码归零并跳过环内旧帧）。之后 Nav 显式订阅（`interval != 0`）仍按原逻辑生效；若首帧本身就是 `0x04 interval=1`，默认直传关闭且显式 GGA 订阅生效。
3. **Survey 显式订阅与 `interval=0` 保护**：
   - `BtLinkModule::applyGnssStreamMask()` 采用“默认直传 ∪ 显式订阅”叠加模型：仅显式订阅的位使用其 `periodMs`，其余默认位保持 0（不节流）；Survey 发送 `0x04/0x05/0x21/0x22/0x23` 且 `interval == 0` 仅回应答，不关闭默认直传；仅在有效掩码真正变化时才调用 `gnssAppRing.setMask()`，避免握手阶段丢弃已入环的 GGA。
   - 断开时 `handleClose()` / `syncStream()` 调用 `resetGnssStreamSession()` 清零默认直传、显式订阅与环内残余（同轮重连场景下 `syncStream()` 仅对已失活的旧 `stream_handle_` 复位，不误清已建立的新 PHONE 会话），下次重连自动按第 1 条重新开启。
4. **满环优先保 GGA（`app::data::GnssAppRing`）与 `gga_drop`**：
   - 为不改动冻结的 `components/app_fw/include/fw/FanoutRing.hpp`，在 `main/data/GnssAppRing.{hpp,cpp}` 实现单写单读、零堆、零初值（保持 `AppContext` 在 `.bss`）的优先级记录环，复用原有 `BootBuffers` 分配的 4096 B 缓冲（零额外 RAM，最大单条仍为 4093 B）。
   - 空间不足时先将未读区压缩至起点（不触碰已 `peek` pin 住的首条记录），再按严格优先级顺序淘汰最旧的低优先级记录：**其它非 GGA（SATS/HEADING）→ GSV → GSA → GST → RMC → GGA**；若环内已被更高优先级记录（如 GGA）占满，新到的低优先级帧直接拒收（返回 `kNoSpace` 并计入 `dropped`），绝不挤掉 GGA。仅当全环皆为 GGA 或受读侧 `pin` 阻塞时才淘汰/丢弃 GGA 并累加 `ggaDropCount()`。
   - 在 `status`、`status gnss`（`SystemStatusCmds.cpp`）与 `gnss status`（`GnssCmdsStatus.cpp`）的 `app_ring` 行新增 `gga_drop=<N>` 输出。
