## 3. 体积对比与增量分析（`builds/t1b` vs `builds/t2` vs `builds/t2-off`）

| 指标（字节） | `builds/t1b` | `builds/t2` (`TRACE=y`) | `t2 - t1b` 增量 | `builds/t2-off` (`TRACE=n`) | `t2 - t2-off` 差值 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Flash Code (`.text`) | 422,944 | 428,696 | +5,752 | 423,356 | +5,340 |
| Flash Data | 122,640 | 125,296 | +2,656 | 122,144 | +3,152 |
| DRAM | 92,869 (74.55%) | 92,893 (74.56%) | **+24** | 84,429 (67.77%) | +8,464 |
| ├ `.data` | 53,125 | 53,141 | +16 | 44,693 | +8,448 |
| └ `.bss` | 39,744 | 39,752 | +8 | 39,736 | +16 |
| IRAM | 82,791 (63.16%) | 82,791 (63.16%) | **0** | 82,791 (63.16%) | 0 |
| Total image | 681,540 | 689,964 | +8,424 | 673,024 | +16,940 |

组件拆解原因：
1. **DRAM 仅增 24 B**：新增命令表与动词表均为 `constexpr` 只读结构，放在 Flash `.rodata`；增量仅来自 `RtcmModule` 速率滑动窗口成员（12 B）、`RtcmStats::bytes_per_sec`（4 B）及 `cli` 注册槽位静态状态（`libcli.a` DRAM 786 → 794 B，+8 B）。
2. **Flash Code +5,752 B / Flash Data +2,656 B**：`libmain.a`（47,908 → 53,406 B，+5,498 B）新增分组命令处理器、`status` 分节、`sys info/heap/tasks/reboot` 与 `log level`；`libesp_stdio.a`（88,085 → 90,316 B，+2,231 B）主要因 `system_cmds.cpp` 与 `rtcm_cmds.cpp` 引入的 `%llu`/`%zu`/`%-*s` 格式化分支与只读表；`libfreertos.a`（22,263 → 22,575 B，+312 B）来自 `sys tasks` 首次链接 `xTaskGetHandle`、`xTaskGetCoreID`、`uxTaskPriorityGet` 与 `xTaskGetIdleTaskHandleForCore`。
3. **`CONFIG_RTK_TRACE_ENABLE=n`（`builds/t2-off`）**：在 `FW_TRACE_ENABLED=0` 下所有命令/系统模块 0 告警通过编译，DRAM 减少 8,464 B、总镜像减少 16,940 B，且 ELF 中不含任何 `TraceRing`/`DebugModule`/`trace_out`/`fw::trace` 符号。

## 5. 与契约的偏离及后续项

1. **`wl add <MAC>` / `wl del <MAC>`**：冻结头 `components/link_core/include/core/link_manager.hpp` 仅提供 `whitelist_clear()` 与只读 `whitelist()`，无单条增删接口，也无按字节/时间参数的 `pair_open` 变长接口；按 T2 任务卡第 1 条要求，未改动冻结头，`wl add/del` 先校验 MAC 格式（非法报 `ERR bad MAC`），合法 MAC 返回 `ERR not supported`；`bt pair <秒>` 仅接受 `60`，其余秒数返回 `ERR only 60s supported`。后续若开放 `link_core` 接口演进，可补全 `LinkManager` 单条白名单增删与可调配对时长。
   - **2026-11-12 已补齐 `wl add/del`**（ADR-0002 §9）：成功 `OK` 并立即持久化；重复添加 `ERR already in whitelist`，删除不存在 `ERR not in whitelist`，满 `ERR whitelist full (4)`。上板已验证（含复位后保留、对端按新白名单以 ALARM 重连）。`bt pair <秒>` 仍只接受 60。
2. **未在板上实测**：按授权边界未连接串口或烧录，§4 控制台转录与 `sys tasks`/`sys info`/`log level`/`sys reboot` 运行时行为需在 T3 上板回归时核对。
3. **遗留静态检查说明**：`tools/main_host_check/template_check.cpp` 沿用了既有的 `CHECK` 宏（`do ... while (false)`），在根 `.clang-tidy` 下存在既有的宏与魔数告警；主固件目标及 `AGENTS.md §5` 指定纯组件与 `rtk_strict_warnings` 编译均 0 告警通过。
