# B1 板级识别、配置表与 P2 电源保持

代码已实现。ESP32 固件构建零告警，普通与 ASan/UBSan 主机测试均通过，冻结清单 188 项通过。G6 注释门禁因本机缺少 `lizard` 而阻塞，HIL 由 Architect 验证。

## 实现

| 文件 | 内容 |
| --- | --- |
| `main/board/BoardProfile.hpp`、`main/board/BoardProfile.cpp`、`main/board/BoardCurrent.cpp` | P2 与 E1 两项静态配置、窗口匹配、板型查询及纯电源保持判定。 |

| `tools/main_host_check/CMakeLists.txt`、`tools/main_host_check/BoardProfileCheck.cpp`、`tools/main_host_check/BootStepsCheck.cpp`、`tools/main_host_check/GnssResetCheck.cpp`、`tools/main_host_check/shim/driver/gpio.h` | 新增配置表和启动顺序检查。现有 GNSS 回归验证 E1 GPIO25 上电、P2 不操作 GNSS 电源脚及 P2 COM1 波特率切换。 |

- `AppContext` 在 ADC、UART 一致性检查和安全输出设置成功后发布静态配置表指针。`current()` 只接受成功识别后的调用，调试版本断言，关闭断言时返回没有有效引脚的 `unknown` 对象。降级诊断先检查指针。
- ADC1 丢弃首样，随后对 8 个原始值四舍五入平均并换算 mV。强制档也完成同一次采样，读 ADC 失败仍会进降级。ADC1 无 eFuse 校准数据时，按 SDK 文档的标称 1100 mV 参考电压和 12 dB 近似衰减进行理想线性换算。ADC2 缺 eFuse 数据时使用 SDK line fitting 的标称参考电压，两个路径均只提示一次。两个步骤的 oneshot 与校准句柄由栈对象释放。
- `checkHold(hold, mv, elapsedMs, streak)` 由调用者保存连续达标数。低于阈值即清零，截止前连续三次达标才成功，恰到 5000 ms 判超时。P2 在拉高按键后集中处理释放，再记录结果。
- ADR-0015 §3 的 COM1 用于 P2。该行所写“同 E1”按 ESP32 侧的 UART2 和 RX/TX 引脚理解，E1 台架档沿用基线的 `RTK_GNSS_PORT` 选择，默认 COM2。锁存芯片型号和最短按压时间仍为 ADR-0015 §4 记载的 `UNKNOWN`，该行为采用 ADR 给定的 5000 ms 界限。

## Architect 验收（Claude，2026-11-18）

结论：**接受**，HIL 待测。评审时修了两处缺陷：

1. `main/board/BoardCurrent.cpp` 中 `current()` 原先对空指针 `assert`。识别失败进入 console-only 后，`gnss raw` 等诊断命令仍会经 `board::gnssReceiverPort()` 调到它；本工程启用了断言（`CONFIG_COMPILER_OPTIMIZATION_ASSERTIONS_ENABLE=y`），结果会 abort 并循环重启。现改为去掉断言，返回无有效引脚的 unknown 配置。
2. `main/board/BoardStartup.cpp` 中 ADC1 缺少 eFuse Vref 时，原先按理想线性换算（4400 mV 满量程）。12 dB 档非线性明显，1.65 V 会读成约 2 V，落出 P2 窗口。现改为照常用 line fitting，Vref 取标称值，同时打一行 W；校准句柄创建失败时返回 `ESP_ERR_INVALID_STATE`。ADR-0015 §2.1 与任务卡已按此同步修订。

复跑门禁（`tools/ci/run_gates.sh`，基线 5a84fe5）：30 PASS / 1 FAIL。G3 idf 默认与 trace-off 均零告警，host 普通与 ASan 全部 PASS，G5b、G7b PASS，frozen 校验 OK，bin 869,152 B。G6 doc_check 为 BLOCKED，原因是本机缺少 `lizard`（按规则禁止联网安装），不是代码问题。

说明：脚本默认找 `~/esp/esp-idf/export.sh`，本机该路径不存在；须先设 `IDF_PYTHON_ENV_PATH=~/.espressif/python_env/idf6.1_py3.13_env`，再 source `~/esp/esp-idf-v6.1/export.sh`。

未覆盖：任务卡 §2 列出的 HIL 1–4 均未执行，`senseOnMv` 1600 mV 阈值还需在实板上校准。
