## 构建、尺寸与堆门禁

基线在开始修改时由 HEAD 导出到 `builds/r2-base-src`，使用同一 ESP-IDF 6.1/GCC 15.2 构建至 `builds/r2-base`；当前工程构建至 `builds/r2`。IDF_COMPONENT_MANAGER=0，未拉取依赖。

| 项目 | HEAD / B | R2 / B | 差值 / B |
| --- | ---: | ---: | ---: |
| DRAM | 83773 | 83797 | +24 |
| .data | 33189 | 44661 | +11472 |
| .bss | 50584 | 39136 | -11448 |
| IRAM | 82779 | 82779 | 0 |
| Flash Code | 415072 | 415652 | +580 |
| Flash Data | 118880 | 118880 | 0 |
| Total image size | 649960 | 662012 | +12052 |

DRAM +24 B 在补充允许的 ±256 B 内，来自 context 引用、会话 sink 的 owner 引用/指针、optional 状态替代原服务指针，以及对象对齐的综合布局变化；没有新增动态分配。`nm -C -S` 显示 s_app 大小为 0x6010（24592 B）。

必须单独说明 Flash 代价：constinit AppContext 内既有非零初始化成员与原先独立的零初始化缓冲合并，原约 11.5 KB 的 .bss 内容转入 .data 初值。因此 DRAM 总量只增加 24 B，但镜像增加 12052 B；这不是协议数据或日志字符串增加。Flash Code 增加 580 B，Flash Data/IRAM 不变。该静态所有权方案保留此代价，没有为压缩镜像重新拆散对象或增加初始化包装。
