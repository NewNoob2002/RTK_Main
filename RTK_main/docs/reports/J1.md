## 3. 契约实现与行为保持

- `Executor` 使用调用方提供的静态栈、TCB、命令队列和结果队列。只初始化/调度所属执行器的模块；init/start 失败只隔离该模块，命令返回 `kInvalidState`。未定义命令回调返回 `kNotSupported`。
- 调度遵守冻结 `executor.hpp` 与 ADR-0007 §3.5：等待钩子/命令队列等待 → 处理命令 → 周期 poll → 更新统计 → 喂狗 → yield。等待和 yield 不计入 round 耗时。积压只影响下一轮等待，仍保留 1 tick yield。BT 等待结束时保存预算起点，命令耗时计入该轮 RX 的 20 ms 预算。
- `call()` 拒绝执行器自调用，单调用者序号匹配，超时不撤销已入队命令；发送前清理旧结果、等待时忽略不匹配结果。结果队列满时丢最旧结果并统计 `result_drops`。统计、任务句柄与 start 可用性变化通过 `stats_mux_` 同步；临界区内不调用 RTOS API。
- `bt_link` 保留原会话表、分流器及回放队列、轮询游标、64 B 预读跨轮保留、整轮 256 B/20 ms 预算、每轮最多一个产品帧、100 ms tick 与 `rx_pending`。继续使用原 `CommandDispatcher`、`LinkService` 和 200 ms 同步写契约。
- RTCM 经内部 `Slot<RtcmBatch>` 从 bt_link 交给 rtcm；批次视图指向 bt_link 的静态缓冲，rtcm 在本轮消费后下一轮 wait 才复用。容量为 `2 × 1029 + 256 = 2314 B`，覆盖两会话遗留数据与每轮新喂入字节。角色拒绝计数一并传递，外部只读取统计主题。两个模块之间没有直接方法调用。
- `rtcm reset` 由 rtcm 的 `on_command` 处理；通过 reset 主题通知 bt_link 清分流统计，保留半帧和会话状态。
- 白名单/SN 使用真实 NVS 命名空间与键名 `rtk/alarm_wl`、`rtk/sn` 的 `StoreKey` 表和序列化绑定。后台白名单变化采用 500 ms 去抖，失败重试 1/2/4/8/16/30/30…秒，新变化不缩短已有失败退避且保存最新 RAM 值。
- 为保持基线控制台输出和错误回执，显式 `wl clear` 仍立即尝试落盘，失败进入同一后台重试；`sn` 仍同步保存，成功后重启生效。bt_link → storage 的通知和显式 flush 为同执行器内单向接口，已在头文件注明。
- 所有要求的主题均有唯一 `constinit Slot<T>`，启动前绑定 `spin_lock_ops`。实际可变存储采用 `s_` 名称，`k*` 主题标识为 `constexpr` 引用，不额外创建 Slot。`kSystemMode` 只登记，默认 `kNormal`，没有状态机。
- kLink 为 core1、priority 10、6144 B 静态栈、20 ms idle wait/round budget、1 tick yield、watchdog。模块表 `constinit`，操作表 `constexpr`，没有新增虚函数。
- 控制台保留 1000 ms 超时、命令名、参数及输出文本；状态读取 Slot，修改经 `Executor::call()`，新增 `exec:` 行。`stats:`、`rtcm:` 的格式字面量及 PRI 宏序列与读取到的基线逐字节对照通过。
- BT 初始化失败仍保留控制台。NVS/SN 的启动准备先于 BT，storage 的 init 幂等，Executor.init 再次经过操作表时不会重复初始化后端。

冻结接口无修改。调度采用冻结头明确规定的轮首等待顺序；后台去抖与显式控制台同步保存的区分如上，未改变协议字节。
