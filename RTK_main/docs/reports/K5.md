## 1. 交付行为与生命周期

- 新增 `rtos::BootArena`，固定 32 项 owner 台账，`UNINIT → OPEN → SEALED / ABORTED`。默认分配器仅使用 `MALLOC_CAP_INTERNAL | MALLOC_CAP_8BIT`，不依赖 PSRAM。重复 owner、无效长度/对齐、长度乘法和对齐取整溢出均拒绝，失败清空输出；类型化分配拒绝低于 `alignof(T)` 的对齐。封存后拒绝分配及释放，析构不回收运行任务可能引用的块。
- 新增外供栈 `BootTask`、外供存储 `BootStreamBuffer`；保留静态 TCB/控制块、静态任务创建和原核/优先级。link：4096 B/core1/prio10；io：4096 B/core0/prio9；SPP worker：2560 B/沿原配置；trace_out：3072 B/沿原配置。ESP-IDF 的栈深度与高水位原始单位均为**字节**，不再额外乘 `sizeof(StackType_t)`。
- 启动顺序为：独立 UART0 console → 全部分配 → 全部绑定 → seal → debug sink/NVS/BT/模块初始化 → link/io/trace 启动屏障 → Running。封存前没有业务任务、驱动或日志 sink 消费这些块。
- 分配或绑定失败：撤销全部已绑定视图，确认 C worker 尚未存在后 abort；所有已成功申请的块释放，进入 console-only。若发现 worker 已持有存储则保留，不冒险释放。
- 封存后失败：应用任务在首次 poll 前等待启动屏障；取消启动时退订 TWDT、确认停稳，再停止 GNSS UART、停驻 SPP worker、等待 SPP UNINIT 并关闭 BT。所有封存块和静态控制对象保留到重启。超时或 SDK 停机失败也保留块，记录首个降级原因。
- console 的命令描述符先注册，通过永久 handler 按阶段放行。Starting/Stopping 返回 `ERR unavailable: booting`；console-only 保留 `status`、`log`、`sys`、`config`，业务组返回 `ERR unavailable: console-only`；正常启动后放行业务。避免冻结 CLI 的“start 后不能增改注册表”限制。
- `sys mem` 经 `cli::Verb/dispatch/out_*` 输出静态段、owner requested/actual/alignment/caps/address、四个能力堆快照及重叠说明、内部堆门槛和降级原因；命令正常结束仍由统一 dispatch 输出 `OK`。`sys heap` 保留。

## 4. 故障注入与回归证据

**PASS**：`tools/main_host_check/boot_alloc_check.cpp` 的四个功能组合直接包含生产分配、绑定、撤销、命令门控和启动准入逻辑；只将硬件装配入口置于 `ESP_PLATFORM` 条件分支。仍对实际被测全局数据启用 ASan，不关闭 sanitizer。

- 每种组合对第一个到最后一个实际 owner 逐次 OOM：失败输出为空、此前所有块释放、台账 ABORTED/清空、原因准确指向 owner；GNSS/Trace 关闭时没有相应 owner。
- 32 项登记表满、重复 owner、零长度、非 2 次幂对齐、低于类型要求的对齐、对齐取整/元素数溢出、重复 open、seal 后分配、重复 seal、UNINIT/OPEN abort 和 SEALED 非法 abort 均有检查。
- 真实 debug、C SPP、GNSS cache/pipe/demux 绑定阶段分别注入无效视图，验证部分绑定撤销和释放后的引用不可用；SEALED abort 不释放且原视图仍有效。
- 静态任务创建通过 GNU ld `--wrap=xTaskCreateStaticPinnedToCore` 检查字节深度与参数，注入创建失败/重试，避免替身 pthread 继续使用测试局部栈；不把替身 task 创建当作硬件调度验证。
- 命令 Starting/ConsoleOnly/Running 放行、业务拒绝、任务准入/取消确认、实际 `sys mem` 格式化器的 requested/actual、caps 重叠说明、最低堆 81920 和最大块 32768 的边界 PASS/FAIL 均有检查。
- `tools/t13_host_check/t13_host_check.c` 新增 `boot_stop`、`boot_stop_failure`、`boot_stop_after_init_failure`：成功停驻禁止重新绑定/重启；SPP deinit 失败后迟到 DATA 回调仍可读出原存储；初始化中途失败后停驻已有 worker。原 TX/拥塞/双会话/迟到 WRITE 等用例全部保留。

此证据覆盖 host 所有权与故障路径，不证明板端 callback 时序、堆碎片、射频吞吐、实际任务高水位或 DRAM 段位置；段位置由本次真实 ELF 独立确认。

过程中发现并修正的失败：旧 BootTask host 用例真实创建 pthread 导致局部 TCB/栈寿命不安全；ASan 保留未使用硬件注册表导致 host 链接失败；T13 shim 缺少 vTaskDelay 声明；G5b 的 optional 生命周期/const/链接地址转换以及外部头环境问题。最终通过方式是修正测试隔离、API 声明和源代码，不关闭 sanitizer/告警。测试专用 free/printf 的辅助 AST 建议按 host 分配器责任及项目禁用 iostream 的规则判为不适用；生产代码不增加忽略。部分 clangd 对跨平台头的主动探测仍超时，未将超时当作 clean；正式 CDB 下的 G5b 与实际 Xtensa 编译均通过。

## 6. 冻结与契约说明

- 依据 K5-dispatch 的具体授权，仅新增三个 rtos 包装头并登记 SHA；既有 rtos/CLI/SPP 公共头保持原 SHA。纯 C storage view 放在非冻结 `boot_include/spp_server_storage.h`，由组件 include 路径导出，没有 C→C++ 调用。
- ADR §7.1 标注为接口草案。本次定稿为 `BootArena::open/allocate/alloc_array/seal/abort/entries`，arena 归 AppContext 所有；没有另设全局分配器单例。台账同时增加 actual/caps/address。`set_degraded_reason` 只在启动事务的 Starting/Stopping 阶段写；控制台在这两个阶段拒绝访问，发布 ConsoleOnly/Running 后只读。
- 为实现整个 AppContext 的全零常量初始化，补改同属 main 的 RtcmModule/StorageModule 上下文绑定；新增 `system_memory.hpp` 只提取实际输出便于无硬件回归。均服务本卡目标，没有新增业务模块或通用执行器副本。
- ADR-0009 的历史 120 KB heap 目标与 ADR-0011 §8.3 的 81920 B 新门槛存在历史差异，使用 K5-dispatch/ADR-0011 的明确门槛，未改冻结文档。启动期堆按 CODING-STYLE 的启动档位登记。
- 未完成/未知：真实 allocator 总耗费及隐藏管理头、板端最低内部堆/最大块、各任务余栈、吞吐与双会话/GNSS 混流不回退均为 **NOT_RUN / UNKNOWN**，不得用 host PASS 替代。没有待修的本地门禁 FAIL 或 BLOCKED。
