# RTK ↔ 报警器 直连协议 v2（提案）

状态：**提案**（2026-11-17，Claude 起草，待用户确认）。v1（0x40/0x41，`phone_protocol.md` §5）已在固件中实现，
本文在其上扩展，**v1 报文的线路格式不变**，v1 报警器固件仍可工作。
相关：`docs/protocol/phone_protocol.md`（帧格式与手机命令）、`components/device_proto/include/DevProtoAlarm.h`（冻结 C 编解码）、
`components/link_core/LinkManager.cpp`（会话准入）、ADR-0007 §5（报警器回连 `bt_reconnect`）。

## 1. 角色与链路

- RTK 是 SPP 服务端；报警器是 SPP 客户端，主动连接并负责断线重连（ADR-0007 Q2）。
- 同时最多 1 部手机 + 1 台报警器（会话上限 2，`SPP_SERVER_MAX_SESSIONS`）。白名单最多 4 台报警器（`kMaxAlarms`）。
- 报警器身份 = 蓝牙 MAC 在白名单中，并在连接后发出 HELLO（§4.2）。配对规则（R4）：白名单设备随时可配对；
  其他设备只在控制台/手机打开的配对窗口内可配对。
- 职责划分：**RTK 决定“是否报警、报警等级”**；报警器只负责发声/提示、本地静音按键和自身状态上报。
  报警器的声音参数由 RTK 保存（NVS）并在每次连接后下发，手机只和 RTK 打交道。

## 2. 帧格式（与 phone_protocol.md §1 完全相同）

```
| AA 44 18 | 0x14 | msg_id u16 | 0×6 | len u16 | 0×2 | sender | type | protocol | interval | payload | CRC32 |
```

- 小端；payload ≤ 256 B；CRC-32/IEEE 覆盖头 + payload。
- `sender`：RTK = `0x01`，报警器 = `0x03`。
- `type`：`0x00` 查询，`0x01` 查询应答，`0x02` 设置，`0x03` 设置应答，`0x04` 主动上报（不应答），`0x05` 错误报告。
- `protocol`（头第 18 字节，v1 置 0）：v2 起填协议版本 `0x02`。接收方不得因该字节拒绝帧；按 HELLO 协商结果决定发哪些报文。
- 结果码 payload：`01 01` 成功，`02 02` 失败/参数非法/不支持（phone_protocol.md §3）。
- 错误报告（type 0x05）payload 4 B：`[0]` 1=CRC 错，2=MSG ID 不支持，3=参数错；其余 0。
- 两端对**未知 msg_id 一律忽略**（不回复、不断链），保证新旧版本混用。

## 3. 报文总表

| ID | 名称 | 方向 | type | 用途 | 版本 |
|---|---|---|---|---|---|
| 0x40 | 报警状态 | RTK → 报警器 | 0x04 上报（1 Hz + 状态变化立即发）；报警器 0x00 查询 → 0x01 应答 | **通知**当前是否报警、等级、原因、RTK 定位/电量 | v1，v2 扩展 |
| 0x41 | 心跳 | 报警器 → RTK | 0x04 | **通知**报警器在线、电量、本地状态 | v1 |
| 0x45 | HELLO / 身份 | 报警器 → RTK | 0x04；RTK 回 0x45 上报 | 连接后首帧：型号、固件版本、协议版本、能力；RTK 回自身信息 | v2 新增 |
| 0x46 | 报警器按键事件 | 报警器 → RTK | 0x02 设置 → RTK 0x03 应答 | **通知/请求** 静音、确认、取消静音、测试键 | v2 新增 |
| 0x47 | 提示参数 | RTK → 报警器 | 0x02 设置 → 报警器 0x03 应答；RTK 0x00 查询 → 0x01 应答 | **设置**音量、每级音型、静音时长、链路丢失提示 | v2 新增 |
| 0x48 | 试响 / 寻找报警器 | RTK → 报警器 | 0x02 → 0x03 | **设置**立即按指定音型响 N 秒（联调、找设备） | v2 新增 |
| 0x49 | 链路控制 | RTK → 报警器 | 0x04 | **通知** RTK 即将关机/重启/解除绑定，报警器据此不报“链路丢失”或忘记配对 | v2 新增 |
| 0x4A | 报警器信息查询 | RTK → 报警器 | 0x00 → 0x01 | **查询**报警器序列号、硬件版本、累计鸣响次数等（售后诊断） | v2 新增，可选 |

手机侧相关命令（手机 → RTK，不经过报警器，见 phone_protocol.md §5）：0x42 测试报警、0x43 电子围栏、0x44 报警器配对/白名单。
v2 建议给手机增加：0x44 查询应答里带报警器在线/电量（§6），以及 0x47 的手机设置入口（同 payload，由 RTK 存 NVS 后转发）。

## 4. 报文定义

### 4.1 0x40 报警状态（RTK → 报警器）

v1 16 B 字段不变；v2 追加 8 B（总 24 B）。v1 报警器按 `len ≥ 16` 解析、忽略多余字节，因此兼容。

| 偏移 | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u16 | seq | 每次推送 +1，回绕；查询应答为 0 |
| 2 | u8 | state | 0 正常，1 报警，2 无定位，0xFF 未知 |
| 3 | u8 | level | 0 不响，1–3 强度（报警器按 0x47 的音型播放） |
| 4 | u8 | fix_quality | GGA 质量（0 无效，1 单点，2 差分，4 固定，5 浮动），0xFF 未知 |
| 5 | u8 | rtk_battery | RTK 电量 %，0xFF 未知 |
| 6 | u8 | flags | bit0 手机在线；bit1 测试覆盖生效；**bit2 已被静音（v2）**；**bit3 RTK 低电（v2）** |
| 7 | u8 | 0 | |
| 8 | u32 | uptime_ms | RTK 运行时间 |
| 12 | u8[4] | 0 | |
| 16 | u8 | reason（v2） | 报警原因：0 无，1 越出围栏，2 失去定位，3 定位降级（固定→浮动/单点），4 RTK 低电，5 手机测试，0xFF 其他 |
| 17 | u8 | fence_id（v2） | 触发的围栏编号，0xFF 无 |
| 18 | u16 | event_id（v2） | 报警事件编号：每次从“不报警”进入“报警”+1；同一事件持续期间不变，供 0x46 确认/静音引用 |
| 20 | u16 | mute_left_s（v2） | 静音剩余秒数，0 未静音 |
| 22 | u8[2] | 0 | |

发送规则：1000 ms 周期；`state`/`level`/`reason`/`event_id`/静音状态变化时**立即**补发一帧（不等周期）。

### 4.2 0x45 HELLO / 身份（双向，v2）

报警器连接成功后**首帧**发送；RTK 收到后回一帧 0x45（sender 0x01）。v1 报警器不发 0x45，RTK 继续把第一帧 0x41
当作 HELLO（现有行为）。

报警器 → RTK（32 B）：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | proto_ver = 2 |
| 1 | u8 | device_type：1 = 外置扬声器报警器（ExternalSpeak），其他预留 |
| 2 | u16 | caps：bit0 扬声器，bit1 LED，bit2 振动，bit3 静音按键，bit4 电池，bit5 支持 0x47，bit6 支持 0x48 |
| 4 | char[12] | fw_version（ASCII，不足补 0） |
| 16 | char[16] | serial（ASCII，不足补 0） |

RTK → 报警器（32 B）：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | proto_ver = 2 |
| 1 | u8 | accepted：1 接受，0 拒绝（随后 RTK 断开；例如不在白名单且不在配对窗口） |
| 2 | u16 | rtk_caps：bit0 电子围栏，bit1 定位降级报警，bit2 低电报警 |
| 4 | char[12] | rtk_fw_version |
| 16 | char[16] | rtk_serial |

握手完成后 RTK 立即发送 0x47（当前提示参数）和一帧 0x40。

### 4.3 0x41 心跳（报警器 → RTK，v1 不变）

8 B：`[0..1]` seq，`[2]` 报警器电量 %（0xFF 未知），`[3]` 本地状态（0 空闲，1 鸣响中，2 已静音），`[4..7]` 0。
周期 1000 ms。RTK 3000 ms 收不到任何有效帧即断开；报警器 3000 ms 收不到 0x40 即进入“链路丢失”处理（§5）。

### 4.4 0x46 报警器按键事件（报警器 → RTK，v2）

payload 4 B：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | action：1 静音当前报警，2 确认（结束本次事件的提示，直到下一次事件），3 取消静音，4 测试键（请求 RTK 下发 0x48 试响） |
| 1 | u8 | 0 |
| 2 | u16 | event_id：针对的报警事件（来自 0x40）；action 3/4 填 0 |

RTK 应答 `01 01` 并在下一帧 0x40 反映（flags bit2、mute_left_s）；event_id 已过期回 `02 02`。
静音时长取 0x47 的 `mute_s`。RTK 把静音/确认通知手机（手机侧报文另定）。

### 4.5 0x47 提示参数（RTK → 报警器，v2）

RTK 保存在 NVS（建议组 `alarm.tone`），连接握手后下发一次，参数变化时再下发。payload 16 B：

| 偏移 | 类型 | 字段 |
|---|---|---|
| 0 | u8 | volume：0–100 % |
| 1 | u8 | tone_level1：音型编号（0 静默，1 慢间断，2 快间断，3 连续，4 双音，其他预留） |
| 2 | u8 | tone_level2 |
| 3 | u8 | tone_level3 |
| 4 | u16 | mute_s：按键静音时长，秒（0 = 只静音本次事件） |
| 6 | u8 | link_lost_tone：链路丢失时的音型，0 不响 |
| 7 | u8 | link_lost_delay_s：丢失多少秒后开始提示（建议默认 10） |
| 8 | u8 | led_enable：0/1 |
| 9 | u8 | vibrate_enable：0/1 |
| 10 | u8[6] | 0 |

报警器应答 `01 01`；不支持的字段忽略但仍回成功，参数越界回 `02 02`。RTK 用 0x00 查询可读回报警器当前生效值（同 16 B）。

### 4.6 0x48 试响（RTK → 报警器，v2）

payload 4 B：`[0]` 音型，`[1]` 音量（0xFF = 用 0x47 的 volume），`[2..3]` 持续秒数 u16（0 = 停止试响）。
报警器应答 `01 01`。来源：手机 0x42、控制台命令、报警器 0x46 action 4。试响不改变 0x40 的 state/event_id。

### 4.7 0x49 链路控制（RTK → 报警器，v2）

payload 4 B：`[0]` 事件：1 RTK 即将关机，2 RTK 即将重启，3 已从白名单移除（报警器应删除本 RTK 的配对并停止回连），
4 RTK 进入配对窗口（报警器可显示）；`[1]` 0；`[2..3]` 预计恢复秒数（重启时填，其余 0）。
报警器收到 1/2 后，在预计时间内断链不按“链路丢失”报警。不应答。

### 4.8 0x4A 报警器信息查询（RTK → 报警器，v2 可选）

查询 payload 2 B 全 0；应答 32 B：`[0..15]` serial，`[16..19]` 硬件版本 ASCII，`[20..23]` 累计鸣响次数 u32，
`[24..27]` 累计运行小时 u32，`[28..31]` 0。用于控制台 `bt alarm info` 和售后。

## 5. 时序

```
报警器                          RTK
  |--- SPP 连接 ------------------>|  LinkManager：白名单 → 角色 ALARM（或窗口内 PENDING）
  |--- 0x45 HELLO (v2) ----------->|  （v1：首帧 0x41 即 HELLO）
  |<-- 0x45 HELLO 应答 ------------|  accepted=0 → RTK 断开
  |<-- 0x47 提示参数 --------------|
  |--- 0x47 应答 01 01 ----------->|
  |<-- 0x40 状态 ------------------|  之后每 1 s，状态变化立即补发
  |--- 0x41 心跳 ----------------->|  每 1 s
  |--- 0x46 静音 (按键) ---------->|
  |<-- 0x46 应答 01 01 ------------|
  |<-- 0x40 flags.bit2=1 ----------|
```

链路丢失：RTK 侧 3 s 无有效帧断开；报警器侧 3 s 无 0x40 视为丢失，`link_lost_delay_s` 后按 `link_lost_tone` 提示，
同时用 `bt_reconnect` 退避回连；收到过 0x49 事件 1/2 时跳过提示。

## 6. RTK 侧需要的改动（实施时拆卡，归入 R4/R5 之后）

- `DevProtoAlarm.h` 是冻结接口：新增 0x45–0x4A 的编解码需新 ADR 批准后扩展（或新增 `DevProtoAlarmV2.h`）。
- `AlarmSource` 增加 reason / event_id / 静音计时；LinkManager 支持 0x45 作为 HELLO。
- NVS 组 `alarm.tone`（0x47 参数）；freset 恢复默认。
- 控制台：`bt alarm list|info|test <tone> <s>|tone ...`。
